# 用户与认证模块

> 本文档描述 DevKit 系统中用户与认证相关的全部功能，包括用户注册、登录、Token 管理、密码管理、设备管理、个人信息、隐私设置、实名认证、角色申请和 OAuth 绑定管理。

---

## 1. 用户注册

### 注册方式

系统支持**用户名 + 邮箱验证码**注册。

### 注册流程

1. 用户填写用户名、邮箱地址
2. 系统发送邮箱验证码（6 位数字，5 分钟有效）
3. 用户输入验证码，设置密码
4. 系统校验用户名和邮箱唯一性
5. 创建用户账号，默认分配普通用户角色
6. 注册成功，自动登录

### 校验规则

| 字段 | 规则 |
|------|------|
| 用户名 | 3-30 个字符，仅允许字母、数字、下划线，不可重复 |
| 邮箱 | 合法邮箱格式，不可重复 |
| 密码 | 8-32 个字符，必须包含大小写字母和数字 |
| 验证码 | 6 位数字，5 分钟内有效，仅可使用一次 |

## 2. 用户登录

系统支持 **7 种登录方式**，覆盖多种使用场景。

### 2.1 用户名密码登录

最基础的登录方式，适用于 Web 管理端。

- 输入用户名和密码
- 完成图形验证码校验
- 登录成功返回 Access Token + Refresh Token

### 2.2 邮箱验证码登录

免密码登录，适用于忘记密码场景。

- 输入邮箱地址
- 发送邮箱验证码
- 输入验证码完成登录

### 2.3 手机号验证码登录

移动端常用登录方式。

- 输入手机号
- 发送短信验证码
- 输入验证码完成登录

### 2.4 OAuth 第三方登录

支持 GitHub、Google 等第三方平台登录。

- 跳转第三方授权页面
- 用户授权后回调
- 系统获取用户信息，自动关联或创建账号

### 2.5 微信小程序登录

移动端微信小程序专用登录。

- 小程序端调用 `wx.login()` 获取 code
- 后端用 code 换取 openid
- 关联或创建用户账号

### 2.6 微信公众号登录

微信公众号内嵌 H5 页面登录。

- 用户在公众号内访问系统
- 跳转微信授权页面
- 授权后获取用户信息，完成登录

### 2.7 微信网页扫码登录

Web 端通过微信扫码登录。

- 生成微信登录二维码
- 用户使用微信扫码并确认
- 系统接收回调，完成登录

### 登录安全策略

| 策略 | 说明 |
|------|------|
| 验证码防护 | 密码登录需完成图形验证码 |
| 失败锁定 | 连续 5 次登录失败，账号锁定 30 分钟 |
| 异地登录 | 检测到异地登录时发送安全通知 |
| 多端控制 | 可配置是否允许多端同时在线（见设备管理） |

## 3. Token 管理

### 双令牌机制

系统采用 **Access Token + Refresh Token** 双令牌认证机制。

| 令牌 | 有效期 | 用途 | 存储位置 |
|------|--------|------|----------|
| Access Token | 7 天 | API 请求认证，放入请求头 `Authorization: Bearer <token>` | 客户端内存/localStorage |
| Refresh Token | 30 天 | 无感刷新 Access Token | 客户端 httpOnly Cookie 或 localStorage |

### Token 刷新流程

```
客户端                          服务端
  │                               │
  │  1. Access Token 过期          │
  │  ──────────────────────────►  │
  │  2. 携带 Refresh Token 请求刷新 │
  │  ──────────────────────────►  │
  │                               │  3. 校验 Refresh Token
  │                               │  4. 生成新的 Access Token + Refresh Token
  │  5. 返回新的 Token 对           │
  │  ◄──────────────────────────  │
  │  6. 更新本地 Token              │
  │  7. 重新发起原始请求             │
  │  ──────────────────────────►  │
```

### Token 轮换（Rotation）

每次刷新 Token 时，旧的 Refresh Token 立即失效，防止令牌泄露后被重复使用。

### Redis 黑名单

- 用户登出时，当前 Access Token 被加入 Redis 黑名单
- 黑名单中的 Token 在过期前均不可使用
- 黑名单自动清理过期条目，避免内存膨胀

## 4. 密码管理

### 4.1 修改密码

- 输入当前密码
- 输入新密码（需符合密码策略）
- 确认新密码
- 修改成功后，其他设备的 Token 全部失效

### 4.2 重置密码

**用户自助重置：**

1. 输入注册邮箱
2. 发送重置密码邮件（包含重置链接，30 分钟有效）
3. 点击链接进入重置页面
4. 设置新密码

**管理员重置：**

- 管理员在用户管理页面可直接重置任意用户密码
- 重置后生成临时密码，用户首次登录时强制修改

### 4.3 密码历史记录

- 系统记录用户最近 5 次密码的哈希值
- 修改密码时检查是否与历史密码重复
- 防止用户反复使用相同密码

### 4.4 强制修改密码

以下场景会触发强制修改密码：

- 管理员重置密码后首次登录
- 密码超过 90 天未修改（可配置）
- 检测到账号安全风险

## 5. 设备管理

### 5.1 查看登录设备

用户可查看当前账号的所有登录设备信息：

| 信息 | 说明 |
|------|------|
| 设备类型 | Web / iOS / Android / 小程序 |
| 设备名称 | 浏览器类型或设备型号 |
| 登录时间 | 该设备的登录时间 |
| 登录 IP | 登录时的 IP 地址 |
| 最后活跃 | 该设备最后一次请求的时间 |
| 当前设备 | 标记当前正在使用的设备 |

### 5.2 踢出设备

- 用户可以踢出任意非当前设备
- 踢出后该设备的 Token 立即失效
- 被踢出设备需要重新登录

### 5.3 多端同时在线控制

系统支持配置多端在线策略：

| 策略 | 说明 |
|------|------|
| 允许多端在线 | 同一账号可在多个设备同时登录（默认） |
| 单端在线 | 新设备登录时，旧设备自动被踢出 |
| 同类型单端 | 同类型设备（如多个 Web 端）只允许一个在线 |

## 6. 个人信息管理

### 可编辑字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 昵称 | string | 用户显示名称，2-20 个字符 |
| 头像 | image | 用户头像，支持上传或选择默认头像 |
| 性别 | enum | 男 / 女 / 保密 |
| 生日 | date | 出生日期 |
| 简介 | text | 个人简介，最多 200 个字符 |

### 头像上传

- 支持 JPG、PNG、GIF、WebP 格式
- 文件大小限制：5MB
- 自动裁剪为正方形
- 生成缩略图用于列表展示

## 7. 隐私设置

用户可控制个人信息的可见性。

### 隐私字段控制

| 字段 | 可选可见范围 | 默认值 |
|------|-------------|--------|
| 邮箱 | 仅自己 / 所有人 | 仅自己 |
| 手机号 | 仅自己 / 所有人 | 仅自己 |
| 生日 | 仅自己 / 所有人 | 仅自己 |
| 性别 | 仅自己 / 所有人 | 所有人 |
| 简介 | 仅自己 / 所有人 | 所有人 |

- 隐私设置仅影响其他用户的查看，不影响管理员
- 修改即时生效，无需重新登录

## 8. 实名认证

### 认证流程

1. 用户提交实名认证申请
   - 真实姓名
   - 身份证号码
   - 身份证正面照片
   - 身份证反面照片
   - 手持身份证照片（可选）
2. 管理员在后台审核
3. 审核通过，用户获得实名认证标识
4. 审核驳回，用户可修改后重新提交

### 认证状态

| 状态 | 说明 |
|------|------|
| 未认证 | 用户未提交认证申请 |
| 待审核 | 已提交申请，等待管理员审核 |
| 已通过 | 认证通过，显示实名标识 |
| 已驳回 | 认证未通过，可查看驳回原因并重新提交 |

## 9. 角色申请

### 申请流程

1. 用户在个人中心发起角色申请
2. 选择要申请的角色（如出题人、审核员）
3. 填写申请理由
4. 提交申请，等待管理员审批
5. 管理员通过或驳回申请
6. 申请通过后，用户获得对应角色权限

### 申请状态

| 状态 | 说明 |
|------|------|
| 待审批 | 申请已提交，等待管理员处理 |
| 已通过 | 申请通过，角色已分配 |
| 已驳回 | 申请未通过，可查看驳回原因 |

### 注意事项

- 已拥有的角色不可重复申请
- 同一角色被驳回后，24 小时内不可重新申请
- 管理员可设置允许用户自主申请的角色列表

## 10. OAuth 绑定管理

### 支持的第三方平台

| 平台 | 绑定方式 | 说明 |
|------|----------|------|
| GitHub | OAuth 2.0 | 开发者常用 |
| Google | OAuth 2.0 | 国际用户 |
| 微信 | 微信开放平台 | 国内用户，支持小程序/公众号/网页 |

### 绑定流程

1. 进入个人中心 → 账号绑定
2. 点击对应平台的「绑定」按钮
3. 跳转第三方授权页面
4. 用户授权后回调系统
5. 绑定成功，显示平台账号信息

### 解绑流程

1. 点击对应平台的「解绑」按钮
2. 确认解绑操作
3. 解绑成功

### 注意事项

- 绑定第三方账号后，可使用该平台账号直接登录
- 解绑后，该平台的登录方式将不可用
- 若账号仅通过第三方注册且未设置密码，解绑前需先设置密码
- 一个第三方账号只能绑定一个系统账号
