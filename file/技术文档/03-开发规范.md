## 1. 代码分层规范

### 层级职责划分

```
┌─────────────────────────────────────────────────────────────┐
│                    Handler 层                                │
│                                                             │
│  职责：                                                      │
│  - HTTP 请求参数绑定（c.ShouldBindJSON）                      │
│  - 参数格式校验（validate.Struct）                            │
│  - 调用 Service 方法                                         │
│  - 格式化统一响应（response.Success / response.BadRequest）    │
│                                                             │
│  禁止：                                                      │
│  - 直接访问数据库                                             │
│  - 包含业务逻辑                                               │
│  - 直接操作 Redis                                             │
│  - 硬编码业务规则                                              │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Service 层                                │
│                                                             │
│  职责：                                                      │
│  - 业务逻辑处理                                               │
│  - 业务规则校验                                               │
│  - 事务管理（db.Transaction）                                 │
│  - 缓存策略（读写 Redis）                                     │
│  - 权限校验（创建者检查、角色检查）                             │
│  - 调用 Repository 方法                                      │
│  - 返回业务错误（error）                                      │
│                                                             │
│  禁止：                                                      │
│  - 直接操作 Gin Context                                      │
│  - 返回 HTTP 响应                                            │
│  - 处理 HTTP 特定逻辑（如 Cookie）                            │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Repository 层                              │
│                                                             │
│  职责：                                                      │
│  - 数据库 CRUD 操作                                          │
│  - GORM 查询构建                                             │
│  - 分页处理（Offset/Limit）                                   │
│  - 关联预加载（Preload）                                      │
│  - 返回 model 或 []model                                    │
│                                                             │
│  禁止：                                                      │
│  - 包含业务逻辑                                               │
│  - 操作 Redis                                                │
│  - 调用其他 Repository                                       │
└─────────────────────────────────────────────────────────────┘
```

### 典型代码示例

#### Handler 层

```go
// internal/handler/question_handler.go

type QuestionHandler struct {
    service *service.QuestionService
}

func NewQuestionHandler(s *service.QuestionService) *QuestionHandler {
    return &QuestionHandler{service: s}
}

func (h *QuestionHandler) Create(c *gin.Context) {
    var req CreateQuestionRequest
    // 1. 参数绑定
    if err := c.ShouldBindJSON(&req); err != nil {
        response.BadRequest(c, "参数格式错误: "+err.Error())
        return
    }

    // 2. 参数校验
    if err := validate.Struct(req); err != nil {
        response.BadRequest(c, "参数校验失败: "+err.Error())
        return
    }

    // 3. 调用 Service
    question, err := h.service.Create(c.Request.Context(), &req)
    if err != nil {
        if errors.Is(err, service.ErrDuplicateQuestion) {
            response.BadRequest(c, "题目已存在")
            return
        }
        logger.Error("创建题目失败", zap.Error(err))
        response.InternalError(c, "创建题目失败")
        return
    }

    // 4. 返回响应
    response.Success(c, question)
}
```

#### Service 层

```go
// internal/service/question_service.go

type QuestionService struct {
    repo     *repository.QuestionRepository
    cache    *cache.RedisCache
}

func NewQuestionService(
    repo *repository.QuestionRepository,
    cache *cache.RedisCache,
) *QuestionService {
    return &QuestionService{repo: repo, cache: cache}
}

func (s *QuestionService) Create(ctx context.Context, req *CreateQuestionRequest) (*model.Question, error) {
    // 1. 业务规则校验
    if req.QuestionType == "" {
        return nil, ErrInvalidQuestionType
    }

    // 2. 构建模型
    question := &model.Question{
        Title:        req.Title,
        QuestionType: req.QuestionType,
        Stem:         req.Stem,
        Status:       "draft",
        CreatedBy:    middleware.GetCurrentUserID(ctx),
    }

    // 3. 调用 Repository
    if err := s.repo.Create(question); err != nil {
        return nil, err
    }

    return question, nil
}
```

#### Repository 层

```go
// internal/repository/question_repo.go

type QuestionRepository struct {
    db *gorm.DB
}

func NewQuestionRepository(db *gorm.DB) *QuestionRepository {
    return &QuestionRepository{db: db}
}

func (r *QuestionRepository) Create(question *model.Question) error {
    return r.db.Create(question).Error
}

func (r *QuestionRepository) GetByID(id uint) (*model.Question, error) {
    var question model.Question
    err := r.db.First(&question, id).Error
    if err != nil {
        return nil, err
    }
    return &question, nil
}

func (r *QuestionRepository) List(req *ListRequest) ([]model.Question, int64, error) {
    var questions []model.Question
    var total int64

    query := r.db.Model(&model.Question{})
    if req.Keyword != "" {
        query = query.Where("title LIKE ?", "%"+req.Keyword+"%")
    }
    if req.Status != "" {
        query = query.Where("status = ?", req.Status)
    }

    query.Count(&total)
    err := query.Offset(req.Offset()).Limit(req.PageSize).
        Order("created_at DESC").
        Find(&questions).Error

    return questions, total, err
}
```

## 2. 命名规范

### 包名

- 全部小写，单个单词
- 避免下划线和混合大小写
- 简短且有意义

```go
// 正确
package service
package repository
package model
package middleware
package response

// 错误
package Service
package service_utils
package svc
```

### 结构体

- 大驼峰命名（PascalCase）
- 名词或名词短语
- 避免缩写（除非是广泛接受的缩写如 ID、URL、HTTP）

```go
// 正确
type UserService struct { ... }
type QuestionRepository struct { ... }
type CreateQuestionRequest struct { ... }

// 错误
type userService struct { ... }
type QuestionRepo struct { ... }
type CreateQuesReq struct { ... }
```

### 方法和函数

- 大驼峰命名（PascalCase，导出）
- 小驼峰命名（camelCase，未导出）
- 动词开头

```go
// 正确
func (s *UserService) GetUserByID(id uint) (*User, error) { ... }
func (s *UserService) validatePassword(pwd string) error { ... }

// 错误
func (s *UserService) get_user(id uint) { ... }
func (s *UserService) User(id uint) { ... }
```

### 常量

- 大写下划线（UPPER_SNAKE_CASE）
- 按功能分组

```go
// 正确
const (
    STATUS_DRAFT     = "draft"
    STATUS_PUBLISHED = "published"
    STATUS_ARCHIVED  = "archived"
)

// 错误
const statusDraft = "draft"
const StatusPublished = "published"
```

### 变量

- 小驼峰命名（camelCase）
- 简短但有意义
- 避免单字符变量（循环变量除外）

```go
// 正确
var userID uint
var questionList []Question
var isDeleted bool

// 错误
var user_id uint
var q []Question
var d bool
```

### 文件名

- 小写下划线（snake_case）
- 按功能模块命名
- 测试文件以 `_test.go` 结尾

```
user_service.go
user_service_test.go
question_handler.go
auth_middleware.go
```

## 3. 错误处理规范

### 错误定义

在 Service 层定义业务错误变量：

```go
// internal/service/errors.go

var (
    // 用户相关
    ErrUserNotFound    = errors.New("用户不存在")
    ErrDuplicateEmail  = errors.New("邮箱已被注册")
    ErrDuplicatePhone  = errors.New("手机号已被注册")
    ErrInvalidPassword = errors.New("密码错误")
    ErrAccountLocked   = errors.New("账号已被锁定")

    // 题目相关
    ErrQuestionNotFound  = errors.New("题目不存在")
    ErrQuestionNotDraft  = errors.New("题目不在草稿状态")
    ErrDuplicateQuestion = errors.New("题目已存在")

    // 权限相关
    ErrPermissionDenied = errors.New("权限不足")
    ErrNotCreator       = errors.New("非创建者无权操作")

    // 文件相关
    ErrFileNotFound  = errors.New("文件不存在")
    ErrFileTooLarge  = errors.New("文件过大")
    ErrInvalidFormat = errors.New("文件格式不支持")
)
```

### Service 层错误处理

```go
func (s *QuestionService) Publish(ctx context.Context, id uint) error {
    question, err := s.repo.GetByID(id)
    if err != nil {
        if errors.Is(err, gorm.ErrRecordNotFound) {
            return ErrQuestionNotFound
        }
        return err // 数据库错误，透传
    }

    // 业务规则校验
    if question.Status != "approved" {
        return ErrQuestionNotDraft
    }

    // 更新状态
    question.Status = "published"
    return s.repo.Update(question)
}
```

### Handler 层错误处理

```go
func (h *QuestionHandler) Publish(c *gin.Context) {
    id, err := strconv.ParseUint(c.Param("id"), 10, 32)
    if err != nil {
        response.BadRequest(c, "无效的题目ID")
        return
    }

    err = h.service.Publish(c.Request.Context(), uint(id))
    if err != nil {
        // 业务错误：返回具体消息
        if errors.Is(err, service.ErrQuestionNotFound) {
            response.NotFound(c, "题目不存在")
            return
        }
        if errors.Is(err, service.ErrQuestionNotDraft) {
            response.BadRequest(c, "题目不在审核通过状态，无法发布")
            return
        }
        // 系统错误：记录日志，返回通用消息
        logger.Error("发布题目失败",
            zap.Uint("id", uint(id)),
            zap.Error(err),
        )
        response.InternalError(c, "发布题目失败")
        return
    }

    response.Success(c, nil)
}
```

### 错误处理原则

1. **Service 层返回具体错误**：使用预定义的错误变量，便于调用方判断
2. **Handler 层区分错误类型**：业务错误返回用户友好的消息，系统错误记录日志
3. **不暴露内部细节**：系统错误只返回通用消息，详细信息写入日志
4. **使用 `errors.Is` 判断**：避免字符串比较

## 4. 响应格式规范

### 统一响应结构

使用 `pkg/response` 包提供的函数：

```go
// 成功响应
response.Success(c, data)
// 返回: {"code": 0, "message": "success", "data": ...}

// 分页响应
response.SuccessPage(c, list, total)
// 返回: {"code": 0, "message": "success", "data": {"list": [...], "total": 100}}

// 错误响应
response.BadRequest(c, "参数错误")     // 400
response.Unauthorized(c, "未登录")     // 401
response.Forbidden(c, "权限不足")      // 403
response.NotFound(c, "资源不存在")     // 404
response.InternalError(c, "服务器错误") // 500
```

### 响应示例

#### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "title": "示例题目",
    "status": "draft"
  }
}
```

#### 分页响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [
      {"id": 1, "title": "题目1"},
      {"id": 2, "title": "题目2"}
    ],
    "total": 100
  }
}
```

#### 错误响应

```json
{
  "code": 400,
  "message": "参数校验失败: Title 字段不能为空"
}
```

### 不使用场景

- 不要直接使用 `c.JSON()` 返回自定义格式
- 不要省略 `message` 字段
- 不要在 `data` 中返回 `nil` 时省略该字段

## 5. 数据库规范

### GORM 模型定义

```go
// internal/model/base.go
type BaseModel struct {
    ID        uint           `gorm:"primaryKey;autoIncrement" json:"id"`
    CreatedAt time.Time      `json:"createdAt"`
    UpdatedAt time.Time      `json:"updatedAt"`
    DeletedAt gorm.DeletedAt `gorm:"index" json:"deletedAt,omitempty"`
}

// internal/model/question.go
type Question struct {
    BaseModel
    Title        string `gorm:"type:varchar(500);not null;index" json:"title"`
    QuestionType string `gorm:"type:varchar(50);not null;index" json:"questionType"`
    Stem         string `gorm:"type:json;not null" json:"stem"`
    Status       string `gorm:"type:varchar(20);default:draft;index" json:"status"`
    CreatedBy    uint   `gorm:"not null;index" json:"createdBy"`
}

func (Question) TableName() string {
    return "qb_questions"
}
```

### 表名映射

- 使用 `TableName()` 方法显式指定表名
- 表名使用下划线命名（snake_case）
- 模块前缀区分：`sys_`（系统）、`qb_`（题库）、`user_`（用户）

```go
func (User) TableName() string { return "sys_users" }
func (Role) TableName() string { return "sys_roles" }
func (Question) TableName() string { return "qb_questions" }
func (PracticeRecord) TableName() string { return "practice_records" }
```

### 软删除

- 使用 GORM 内置的 `gorm.DeletedAt`
- 查询时自动过滤已删除记录
- 需要查询已删除记录时使用 `Unscoped()`

```go
// 自动过滤已删除记录
db.Find(&questions) // 不包含 deleted_at 不为 NULL 的记录

// 包含已删除记录
db.Unscoped().Find(&questions)
```

### 索引设计

- 主键自动索引
- 外键字段添加索引
- 频繁查询的字段添加索引
- 组合查询使用复合索引

```go
type Question struct {
    ID           uint   `gorm:"primaryKey;autoIncrement"`
    Title        string `gorm:"type:varchar(500);not null;index"`
    Status       string `gorm:"type:varchar(20);default:draft;index"`
    ExamID       uint   `gorm:"index"`
    SubjectID    uint   `gorm:"index"`
    CategoryID   uint   `gorm:"index"`
    CreatedBy    uint   `gorm:"not null;index"`
}
```

### JSON 字段

- 使用 `type:json` 存储 JSON 数据
- 在 Go 中使用 `string` 类型存储
- 序列化/反序列化在 Service 层处理

```go
type Role struct {
    ID          uint   `gorm:"primaryKey"`
    Name        string `gorm:"type:varchar(50);not null"`
    Permissions string `gorm:"type:text;comment:权限列表(JSON数组)" json:"permissions"`
}
```

## 6. 中间件使用规范

### 全局中间件

在 `router.Setup()` 中注册，对所有路由生效：

```go
engine := gin.New()

// 全局中间件（顺序重要）
engine.Use(middleware.Logger())           // 1. 请求日志
engine.Use(middleware.SecurityHeaders())  // 2. 安全响应头
engine.Use(middleware.CORS(cfg))         // 3. 跨域
engine.Use(middleware.RateLimiter())     // 4. 全局限流
engine.Use(middleware.DBRateLimiter())   // 5. 数据库限流
engine.Use(middleware.CSRF())            // 6. CSRF 防护
engine.Use(gin.Recovery())               // 7. Panic 恢复
```

### 路由级中间件

在路由注册时指定，仅对特定路由生效：

```go
// 需要认证的路由
auth := engine.Group("/api/v1")
auth.Use(middleware.JWTAuth())
{
    auth.GET("/user/info", userHandler.GetInfo)
    auth.POST("/questions", questionHandler.Create)
}

// 需要特定权限的路由
system := engine.Group("/api/v1/system")
system.Use(middleware.JWTAuth())
system.Use(middleware.SecurityLogMiddleware())
{
    system.GET("/users",
        middleware.Permission("system:user:view"),
        userHandler.List,
    )
    system.POST("/users",
        middleware.Permission("system:user:add"),
        userHandler.Create,
    )
}
```

### 中间件组合模式

| 场景 | 中间件组合 |
|------|-----------|
| 公开接口 | 无额外中间件 |
| 需认证接口 | JWTAuth |
| 需认证 + 日志 | JWTAuth + SecurityLogMiddleware |
| 需认证 + 权限 | JWTAuth + Permission(code) |
| 需认证 + 风控 | JWTAuth + CaptchaGuard |
| 管理后台 | JWTAuth + SecurityLogMiddleware + Permission(code) |

## 7. 缓存使用规范

### Redis 缓存策略

```go
// 缓存键命名规范
const (
    CacheKeyUserPrefix       = "user:"           // user:{id}
    CacheKeyPermPrefix       = "perm:"           // perm:{user_id}
    CacheKeyQuestionPrefix   = "question:"       // question:{id}
    CacheKeyRiskPrefix       = "risk:"           // risk:{ip}
    CacheKeyLoginFailPrefix  = "login_fail:"     // login_fail:ip:{ip} 或 login_fail:user:{username}
    CacheKeyTokenBlacklist   = "token_blacklist:" // token_blacklist:{hash}
)
```

### TTL 设置

| 缓存类型 | TTL | 说明 |
|---------|-----|------|
| 用户权限 | 10 分钟 | 角色变更时主动失效 |
| 风险评分 | 30 分钟 | 自然衰减 |
| 登录失败计数 | 30 分钟 | 成功登录后清除 |
| Token 黑名单 | Token 剩余有效期 | 与 Token 生命周期一致 |
| 验证码白名单 | 10 分钟 | 验证码通过后写入 |
| Refresh Token | 30 天 | 与 Token TTL 一致 |

### 缓存读写模式

```go
// 读取：Cache-Aside 模式
func (s *AuthService) GetPermissionCodes(userID uint) ([]string, error) {
    cacheKey := fmt.Sprintf("perm:%d", userID)

    // 1. 先读缓存
    cached, err := s.cache.Get(cacheKey)
    if err == nil {
        var codes []string
        json.Unmarshal([]byte(cached), &codes)
        return codes, nil
    }

    // 2. 缓存未命中，读数据库
    codes, err := s.loadPermissionCodesFromDB(userID)
    if err != nil {
        return nil, err
    }

    // 3. 写入缓存
    data, _ := json.Marshal(codes)
    s.cache.Set(cacheKey, string(data), 10*time.Minute)

    return codes, nil
}
```

### 缓存失效

```go
// 角色变更时清除相关用户的权限缓存
func (s *RoleService) UpdateRolePermissions(roleID uint, permissions []string) error {
    // 1. 更新数据库
    if err := s.repo.UpdatePermissions(roleID, permissions); err != nil {
        return err
    }

    // 2. 获取该角色的所有用户
    userIDs, err := s.repo.GetUserIDsByRole(roleID)
    if err != nil {
        return err
    }

    // 3. 清除这些用户的权限缓存
    for _, uid := range userIDs {
        s.cache.Delete(fmt.Sprintf("perm:%d", uid))
    }

    return nil
}
```

## 8. 日志规范

### 结构化日志

使用 Zap 结构化日志，避免字符串拼接：

```go
// 正确
logger.Info("用户登录成功",
    zap.Uint("user_id", user.ID),
    zap.String("username", user.Username),
    zap.String("ip", c.ClientIP()),
)

// 错误
logger.Info("用户 " + user.Username + " 登录成功，IP: " + c.ClientIP())
```

### 日志级别使用

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| Debug | 开发调试信息 | SQL 查询、缓存命中/未命中 |
| Info | 正常业务操作 | 用户登录、数据创建、状态变更 |
| Warn | 需要关注但不影响运行 | 限流触发、配置缺失使用默认值 |
| Error | 错误但不影响系统运行 | 单个请求失败、外部服务超时 |
| Fatal | 系统无法启动 | 数据库连接失败、配置解析错误 |

### 敏感信息脱敏

```go
// 正确：脱敏处理
logger.Info("用户注册",
    zap.String("email", maskEmail(user.Email)),  // u***@example.com
    zap.String("phone", maskPhone(user.Phone)),  // 138****1234
)

// 错误：直接输出敏感信息
logger.Info("用户注册",
    zap.String("email", user.Email),
    zap.String("password", req.Password),  // 绝对不能记录密码
    zap.String("id_card", user.IDCard),
)
```

### 错误日志

```go
// 记录完整的错误上下文
logger.Error("创建题目失败",
    zap.Uint("user_id", userID),
    zap.String("question_type", req.QuestionType),
    zap.Error(err),  // 原始错误
)

// 避免只记录错误消息
logger.Error("创建题目失败: " + err.Error())
```

## 9. Git 提交规范

### 提交格式

```
type(scope): subject

body

footer
```

### 类型（type）

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响功能） |
| `refactor` | 重构（既不是新功能也不是修复） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具变更 |
| `ci` | CI 配置变更 |

### 范围（scope）

可选，表示影响范围：

| 范围 | 说明 |
|------|------|
| `auth` | 认证模块 |
| `user` | 用户模块 |
| `question` | 题库模块 |
| `file` | 文件模块 |

| `middleware` | 中间件 |

| `api` | API 接口 |

### 示例

```bash
# 新功能
git commit -m "feat(question): 添加题目批量导入功能"

# Bug 修复
git commit -m "fix(auth): 修复 Refresh Token 并发刷新问题"

# 文档
git commit -m "docs: 更新 API 文档"

# 重构
git commit -m "refactor(storage): 重构存储管理器初始化逻辑"

# 性能优化
git commit -m "perf(query): 优化题目列表查询性能"

# 带详细说明
git commit -m "feat(auth): 添加风险评分系统

- 基于 IP 的请求频率监控
- User-Agent 异常检测
- 无 Referer 请求检测
- 验证码触发阈值配置化

Closes #123"
```

### 提交规范

1. **一个提交做一件事**：不要混合多个不相关的变更
2. **提交消息使用中文**：subject 使用中文描述
3. **首字母小写**：subject 首字母小写
4. **不加句号**：subject 末尾不加标点
5. **使用祈使语气**：使用"添加"而不是"添加了"
