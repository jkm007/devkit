## 1. 整体架构

DevKit 后端采用**单体 Go 应用**架构，基于 Gin Web 框架构建，遵循经典的**分层架构**模式：

```
┌─────────────────────────────────────────────────────────────┐
│                      HTTP Client                            │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Gin HTTP Engine                           │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              全局中间件链                              │   │
│  │  Logger → SecurityHeaders → CORS → RateLimiter       │   │
│  │  → DBRateLimiter → CSRF → Recovery                   │   │
│  └──────────────────────────────────────────────────────┘   │
│                          │                                   │
│  ┌──────────────────────────────────────────────────────┐   │
│  │              路由级中间件                              │   │
│  │  JWTAuth → Permission → CaptchaGuard → SecurityLog   │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Handler 层 (HTTP)                        │
│         参数绑定 · 请求校验 · 响应格式化                      │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                    Service 层 (业务)                        │
│         业务逻辑 · 事务管理 · 缓存策略 · 权限校验              │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Repository 层 (数据)                      │
│         数据访问 · SQL 构建 · 分页查询                        │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────┬──────────────────────────────────┐
│       MySQL (GORM)       │         Redis                    │
│    持久化数据存储          │    缓存 · 会话 · 限流             │
└──────────────────────────┴──────────────────────────────────┘
```

### 设计原则

- **单一职责**：每层只负责自己的职责，Handler 不包含业务逻辑，Repository 不包含业务规则
- **依赖注入**：通过构造函数注入依赖，便于测试和解耦
- **接口抽象**：存储、缓存等基础设施通过接口定义，支持多种实现
- **配置驱动**：所有可变配置通过 Viper 统一管理，支持环境变量覆盖

## 3. 启动流程

应用启动是一个严格的顺序过程，任何步骤失败都会导致启动中止：

```
┌─────────────────────────────────────────────────────────────┐
│                    main() 启动流程                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ① 加载配置                                                 │
│     config.Load("config/config.yaml")                       │
│     └─ Viper 解析 YAML + 环境变量覆盖                        │
│                                                             │
│  ② 密钥校验                                                 │
│     validateSecrets(cfg)                                    │
│     └─ 拒绝 JWT_SECRET/AES_KEY/CAPTCHA_SECRET 的占位值      │
│                                                             │
│  ③ 日志初始化                                               │
│     logger.Init(cfg.Log)                                    │
│     └─ Zap 结构化日志 + 文件轮转                              │
│     └─ 初始化验证码密钥、OAuth 提供者、风险评分配置             │
│                                                             │
│  ④ MySQL 连接                                               │
│     database.InitMySQL(cfg.MySQL)                           │
│     └─ GORM 连接池（max_open_conns / max_idle_conns）        │
│                                                             │
│  ⑤ Redis 连接                                               │
│     database.InitRedis(cfg.Redis)                           │
│     └─ go-redis 客户端（pool_size）                          │
│                                                             │
│  ⑥ 数据库迁移                                               │
│     migrations.Run(db)                                      │
│     └─ GORM AutoMigrate 55 个模型                            │
│                                                             │
│  ⑦ 默认用户初始化                                            │
│     authService.InitDefaultUsers()                          │
│     └─ 创建 super/admin/user 角色 + 默认管理员                │
│     └─ 密码从环境变量读取或随机生成 16 位                      │
│                                                             │
│  ⑧ 存储设置初始化                                             │
│     service.InitDefaultStorageSettings(cfg.Storage)          │
│     service.InitDefaultStorageBuckets()                      │
│     └─ 写入 sys_system_settings 和 sys_storage_bucket        │
│                                                             │
│  ⑨ WebSocket Hub                                            │
│     hub := ws.NewHub()                                      │
│     go hub.Run()                                            │
│     service.SetGlobalHub(hub)                               │
│                                                             │
│  ⑩ 文件类型规则加载                                           │
│     initFileTypeRules()                                     │
│     └─ 从 sys_file_type_rules 加载到 AutoTagger              │
│                                                             │
│  ⑪ 存储初始化                                                │
│     storage.InitStorage(cfg.Storage)                        │
│     └─ 确定活跃驱动 → 创建存储实例 → 缓存                     │
│                                                             │
│  ⑫ 路由引擎初始化                                             │
│     storage.InitRoutingEngine()                             │
│     └─ 从 sys_tag_routing 加载规则                           │
│                                                             │
│  ⑬ 定时任务                                                 │
│     service.InitScheduledTasks()                            │
│     └─ 注册定时清理/统计等任务                                │
│                                                             │
│  ⑭ 路由注册                                                 │
│     engine := router.Setup(ctx, cfg, hub)                   │
│     └─ 全局中间件 + 路由分组 + 权限绑定                       │
│                                                             │
│  ⑮ HTTP 服务启动                                             │
│     srv.ListenAndServe()                                    │
│     └─ 监听配置端口（默认 8080）                              │
│                                                             │
│  ⑯ 优雅退出                                                 │
│     signal.Notify(SIGINT, SIGTERM)                          │
│     hub.Stop()                                              │
│     srv.Shutdown(5s timeout)                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 关键依赖顺序

| 步骤 | 依赖 | 原因 |
|------|------|------|
| ⑥ 迁移 | ④ MySQL | 需要数据库连接 |
| ⑦ 默认用户 | ⑥ 迁移 | 表必须已创建 |
| ⑧ 存储设置 | ④ MySQL + ⑤ Redis | 写入数据库和缓存 |
| ⑩ 文件类型 | ④ MySQL | 从数据库加载规则 |
| ⑪ 存储初始化 | ⑧ 存储设置 | 依赖系统设置数据 |
| ⑫ 路由引擎 | ④ MySQL | 从数据库加载路由规则 |
| ⑭ 路由注册 | 所有中间件和服务 | 需要完整的依赖链 |

## 4. 请求处理流程

### 完整请求生命周期

```
客户端请求
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│                   全局中间件链                                │
│                                                             │
│  ① Logger          记录请求日志（method/path/IP/latency）     │
│  ② SecurityHeaders 设置安全响应头                             │
│  ③ CORS            处理跨域预检和响应                          │
│  ④ RateLimiter     全局 IP 令牌桶限流                         │
│  ⑤ DBRateLimiter   数据库驱动的精细限流规则                    │
│  ⑥ CSRF            Double Submit Cookie 防护                 │
│  ⑦ Recovery        Panic 恢复，返回 500                      │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   路由匹配                                   │
│  Gin 路由树匹配 → 确定 Handler + 路由级中间件                  │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   路由级中间件（按需组合）                     │
│                                                             │
│  ① JWTAuth         Token 提取 → 解析 → 黑名单检查            │
│                    → 设备踢出检查 → 写入 Context              │
│                                                             │
│  ② Permission      从 Redis 缓存获取权限码                    │
│                    → 匹配 requiredCode                        │
│                                                             │
│  ③ CaptchaGuard    风险评分累加 → 超阈值触发验证码             │
│                    → 验证通过后白名单 10 分钟                  │
│                                                             │
│  ④ SecurityLog     拦截写操作 → 记录异步安全日志               │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Handler 层                                 │
│                                                             │
│  c.ShouldBindJSON(&req)     参数绑定                         │
│  validate.Struct(req)        参数校验                         │
│  service.Method(req)         调用 Service                     │
│  response.Success(c, data)   统一响应                         │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Service 层                                 │
│                                                             │
│  业务逻辑处理                                                │
│  权限校验（如创建者检查）                                      │
│  事务管理（db.Transaction）                                   │
│  缓存读写（Redis）                                           │
│  调用 Repository                                             │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                   Repository 层                              │
│                                                             │
│  GORM 查询构建                                               │
│  分页处理（Offset/Limit）                                     │
│  关联预加载（Preload）                                        │
│  返回 model 或 []model                                      │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌──────────────────────────┬──────────────────────────────────┐
│       MySQL              │         Redis                    │
│   CRUD / 事务            │   缓存 / 会话 / 限流              │
└──────────────────────────┴──────────────────────────────────┘
```

### 中间件执行顺序详解

| 顺序 | 中间件 | 作用范围 | 失败行为 |
|------|--------|---------|---------|
| 1 | Logger | 所有请求 | 不阻断 |
| 2 | SecurityHeaders | 所有请求 | 不阻断 |
| 3 | CORS | 所有请求 | 预检失败返回 403 |
| 4 | RateLimiter | 所有请求 | 超限返回 429 |
| 5 | DBRateLimiter | 所有请求 | 超限返回 429 + 累加风险分 |
| 6 | CSRF | 非安全方法 | 校验失败返回 403 |
| 7 | Recovery | 所有请求 | Panic 返回 500 |
| 8 | JWTAuth | 需认证路由 | 无/无效 Token 返回 401 |
| 9 | Permission | 管理路由 | 权限不足返回 403 |
| 10 | CaptchaGuard | 需保护路由 | 需验证码返回 403 |
| 11 | SecurityLog | 写操作路由 | 不阻断（异步记录） |

## 6. 依赖注入模式

系统采用**构造函数注入**模式，Service 层通过构造函数接收 Repository 依赖：

### 典型注入链

```go
// Repository 层
type UserRepository struct {
    db *gorm.DB
}

func NewUserRepository(db *gorm.DB) *UserRepository {
    return &UserRepository{db: db}
}

// Service 层
type UserService struct {
    repo      *repository.UserRepository
    roleRepo  *repository.RoleRepository
    cache     *cache.RedisCache
}

func NewUserService(
    repo *repository.UserRepository,
    roleRepo *repository.RoleRepository,
    cache *cache.RedisCache,
) *UserService {
    return &UserService{
        repo:     repo,
        roleRepo: roleRepo,
        cache:    cache,
    }
}

// Handler 层（大多数 Handler 使用零参数构造函数，内部自行创建 Service）
type UserHandler struct {
    service *service.UserService
}

func NewUserHandler() *UserHandler {
    return &UserHandler{
        service: service.NewUserService(),
    }
}
```

### 路由注册中的依赖组装

在 `router.Setup()` 中完成所有依赖的组装：

```go
func Setup(ctx context.Context, cfg *config.Config, hub *ws.Hub) *gin.Engine {
    db := database.GetMySQL()
    rdb := database.GetRedis()

    // Repository 层
    userRepo := repository.NewUserRepository(db)
    roleRepo := repository.NewRoleRepository(db)
    questionRepo := repository.NewQuestionRepository(db)
    // ...

    // Service 层
    authService := service.NewAuthService(userRepo, roleRepo, rdb)
    userService := service.NewUserService(userRepo, roleRepo, rdb)
    questionService := service.NewQuestionService(questionRepo, rdb)
    // ...

    // Handler 层（大多数 Handler 使用零参数构造函数，内部自行创建 Service）
    authHandler := handler.NewAuthHandler()
    userHandler := handler.NewUserHandler()
    questionHandler := handler.NewQuestionHandler()
    // 少数 Handler 接受 Service 参数：
    tagHandler := handler.NewTagHandler(service.NewTagService(...))
    routingHandler := handler.NewRoutingHandler(service.NewRoutingService(...))
    storageBucketHandler := handler.NewStorageBucketHandler(service.NewStorageBucketService(...))
    // ...

    // 路由注册
    engine := gin.New()
    // 全局中间件
    engine.Use(middleware.Logger())
    // ... 路由分组
}
```

### 全局单例外的服务

部分服务使用全局单例模式（通过包级变量 + setter）：

```go
// pkg/storage/manager.go
var (
    currentStorage Storage
    storageMutex   sync.RWMutex
    storageCache   = make(map[string]Storage)
    routingEngine  *RoutingEngine
)

// internal/service/auth_service.go
var globalHub *ws.Hub

func SetGlobalHub(h *ws.Hub) {
    globalHub = h
}
```

这种模式用于需要跨多个 Service 共享的基础设施组件。

## 7. 错误处理策略

### 错误分类

系统将错误分为两类，采用不同的处理策略：

| 错误类型 | 示例 | HTTP 状态码 | 响应格式 |
|---------|------|------------|---------|
| 用户输入错误 | 参数校验失败、用户名已存在、密码错误 | 400/401/403/404 | 包含用户可读的错误消息 |
| 系统内部错误 | 数据库连接失败、Redis 超时 | 500 | 通用错误消息，详细信息写入日志 |

### 统一响应格式

使用 `pkg/response` 包提供标准化的响应：

```go
// 成功响应
response.Success(c, data)           // 200, {code: 0, message: "success", data: ...}
response.SuccessPage(c, list, total) // 200, {code: 0, message: "success", data: {list: [], total: N}}

// 错误响应
response.BadRequest(c, "参数错误")    // 400
response.Unauthorized(c, "未登录")    // 401
response.Forbidden(c, "权限不足")     // 403
response.NotFound(c, "资源不存在")    // 404
response.InternalError(c, "服务器错误") // 500
```

### Handler 层错误处理模式

```go
func (h *QuestionHandler) Create(c *gin.Context) {
    var req CreateQuestionRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        response.BadRequest(c, "参数格式错误: "+err.Error())
        return
    }

    if err := validate.Struct(req); err != nil {
        response.BadRequest(c, "参数校验失败: "+err.Error())
        return
    }

    question, err := h.service.Create(c.Request.Context(), &req)
    if err != nil {
        // 区分业务错误和系统错误
        if errors.Is(err, service.ErrDuplicateQuestion) {
            response.BadRequest(c, "题目已存在")
            return
        }
        // 系统错误：记录日志，返回通用消息
        logger.Error("创建题目失败", zap.Error(err))
        response.InternalError(c, "创建题目失败")
        return
    }

    response.Success(c, question)
}
```

### Service 层错误定义

```go
var (
    ErrUserNotFound       = errors.New("用户不存在")
    ErrDuplicateEmail     = errors.New("邮箱已被注册")
    ErrInvalidPassword    = errors.New("密码错误")
    ErrQuestionNotDraft   = errors.New("题目不在草稿状态")
    ErrPermissionDenied   = errors.New("权限不足")
)
```

Service 层返回具体的业务错误，Handler 层负责将错误转换为用户友好的响应消息。

## 8. 配置管理

### 配置结构总览

```go
type Config struct {
    Server    ServerConfig     // 服务器：端口、模式、超时
    MySQL     MySQLConfig      // 数据库：连接池配置
    Redis     RedisConfig      // 缓存：连接配置
    JWT       JWTConfig        // 认证：密钥、TTL
    Log       LogConfig        // 日志：级别、格式、轮转
    CORS      CORSConfig       // 跨域：允许源、方法
    RateLimit RateLimitConfig  // 限流：速率、突发
    Storage   StorageConfig    // 存储：驱动、各后端配置
    CDN       CDNConfig        // CDN：域名、图片样式
    ClamAV    ClamAVConfig     // 病毒扫描：开关、Socket
    Crypto    CryptoConfig     // 加密：AES 密钥
    Captcha   CaptchaConfig    // 验证码：尺寸、密钥
    SMS       SMSConfig        // 短信：驱动、阿里云/腾讯云
    Email     EmailConfig      // 邮件：SMTP 配置
    WeChat    WeChatConfig     // 微信：小程序/公众号/网页
    OAuth     OAuthConfig      // OAuth：GitHub/Google/微信
}
```

### 环境变量覆盖

Viper 的 `AutomaticEnv()` 支持通过环境变量覆盖任何配置项。关键安全配置**必须**通过环境变量设置：

| 环境变量 | 配置路径 | 说明 |
|---------|---------|------|
| `JWT_SECRET` | `jwt.secret` | JWT 签名密钥 |
| `AES_KEY` | `crypto.aes_key` | AES-256 加密密钥 |
| `CAPTCHA_SECRET` | `captcha.secret` | 验证码加密密钥 |

启动时 `validateSecrets()` 会拒绝包含 `changeme` 占位值的配置。
