## 2. 设计原则

### 2.1 GORM AutoMigrate

- 使用 GORM 的 AutoMigrate 机制自动管理表结构变更
- 应用启动时自动执行迁移，确保表结构与模型定义一致
- 迁移入口：`migrations/migrate.go`，统一管理所有模型的迁移注册

### 2.2 软删除

- 所有业务表均使用软删除（`gorm.DeletedAt`）
- 软删除字段：`deleted_at`，类型为 `DATETIME`，可为 `NULL`
- 记录删除时设置 `deleted_at` 为当前时间，查询时自动过滤已删除记录
- 物理删除需手动执行 SQL：`DELETE FROM table_name WHERE deleted_at IS NOT NULL`

### 2.3 外键关系

- 关联表通过业务字段（如 `user_id`、`role_id`）建立逻辑外键
- 不使用数据库层面的物理外键约束，由应用层保证数据一致性
- 关联查询使用 GORM 的 `Preload` 或 `Joins` 方法

### 2.4 索引设计

- 主键索引：所有表使用自增 `ID` 作为主键
- 唯一索引：用于保证业务唯一性（如用户名、邮箱、手机号）
- 普通索引：用于高频查询字段（如 `user_id`、`status`、`created_at`）
- 复合索引：用于多条件组合查询场景
- 软删除索引：所有表的 `deleted_at` 字段均建立索引

## 4. 命名规范

### 4.1 表名规范

- 全部使用小写字母 + 下划线命名
- 系统管理表以 `sys_` 为前缀
- 题库相关表以 `qb_` 为前缀
- 业务表不使用前缀
- 关联表使用两个实体名拼接：`sys_user_roles`、`sys_group_roles`

### 4.2 字段名规范

- 全部使用小写字母 + 下划线命名
- 主键统一命名为 `id`
- 外键字段命名为 `{关联表名去前缀}_id`，如 `user_id`、`role_id`
- 时间字段使用 `_at` 后缀：`created_at`、`updated_at`、`deleted_at`
- 布尔字段使用 `is_` 前缀：`is_real`、`is_mastered`

### 4.3 索引命名规范

| 索引类型 | 命名格式 | 示例 |
|----------|----------|------|
| 普通索引 | `idx_{表名}_{字段名}` | `idx_sys_users_email` |
| 唯一索引 | `uniq_{表名}_{字段名}` | `uniq_sys_users_name` |
| 复合索引 | `idx_{表名}_{字段1}_{字段2}` | `idx_sys_security_logs_user_id_event_type` |

## 5. 数据库连接池配置

### 5.1 MySQL 连接池

| 参数 | 值 | 说明 |
|------|-----|------|
| MaxOpenConns | 100 | 最大打开连接数 |
| MaxIdleConns | 10 | 最大空闲连接数 |
| ConnMaxLifetime | 3600s | 连接最大存活时间（1小时） |

**配置位置**：`config/config.yaml` → `mysql` 节点

**初始化代码**：`pkg/database/mysql.go`

```go
db.DB().SetMaxOpenConns(cfg.MaxOpenConns)
db.DB().SetMaxIdleConns(cfg.MaxIdleConns)
db.DB().SetConnMaxLifetime(cfg.ConnMaxLifetime)
```

| 参数 | 值 | 说明 |

| PoolSize | 100 | 连接池最大连接数 |
| DB | 0 | 使用的数据库编号 |

**初始化代码**：`pkg/database/redis.go`

## 6. Redis 使用场景

| 场景 | Key 格式 | TTL | 说明 |
|------|----------|-----|------|
| Token 黑名单 | `token:blacklist:{jti}` | Token剩余有效期 | 用户登出/修改密码后使 Token 失效 |
| 验证码存储 | `verify:code:{biz}:{target}` | 5分钟 | 存储邮箱/手机验证码的哈希值 |
| 权限缓存 | `user:permissions:{user_id}` | 10分钟 | 缓存用户权限码列表，减少数据库查询 |
| 风险评分 | `captcha:risk:{ip}` | 滑动窗口 | 记录请求时间戳，计算风险分数 |
| 延迟任务队列 | Redis List/Sorted Set | - | 异步任务处理（如文件清理） |
| 限流计数器 | `ratelimit:{path}:{identifier}` | 规则定义 | 滑动窗口限流，防止接口滥用 |
| 设备踢出标记 | `device:kicked:{device_id}` | 5分钟 | 标记被踢出的登录设备 |
| 验证码白名单 | `captcha:whitelist:{ip}` | 24小时 | 通过验证码后短期免验证 |
| Banner 缓存 | `banner:list` | 5分钟 | 缓存轮播图列表，减少数据库查询 |
| 媒体 URL 缓存 | `media:url:{file_id}` | 5天 | 缓存预签名 URL，避免重复生成 |

## 7. 迁移策略

### 7.1 自动迁移

- 使用 GORM 的 `AutoMigrate` 方法进行表结构自动迁移
- 应用启动时自动执行，无需手动干预
- 支持新增表、新增字段、新增索引
- 不支持删除字段、修改字段类型（需手动 SQL 处理）

### 7.2 迁移管理

**入口文件**：`migrations/migrate.go`

迁移注册方式：

```go
db.AutoMigrate(
    // 系统管理
    &model.User{},
    &model.Role{},
    &model.Menu{},
    &model.Group{},
    // ... 更多模型
)
```

### 7.3 SQL 迁移脚本

对于 AutoMigrate 无法处理的变更（如数据修复、字段删除），使用手动 SQL 脚本：

| 文件 | 说明 |
|------|------|
| `schema.sql` | 完整基础表结构（41KB） |
| `fix_roleapp_duplicate_authcode.sql` | 修复角色申请重复权限码 |
| `20240615_add_mobile_config_menus.sql` | 添加移动端配置菜单 |
| `20260612_add_notification_system.sql` | 通知系统表 |
| `20260612_add_question_bank_*.sql` | 题库功能（6个文件） |
| `20260612_add_question_version_and_fixes.sql` | 题目版本和修复 |
| `20260616_add_mobile_config_tables.sql` | 移动端配置表 |
