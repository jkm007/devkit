## 1. sys_file_entries 文件条目表

**说明**：用户文件系统中的文件条目表，记录用户上传的文件信息。支持软删除和回收站机制。

**软删除**：自定义（`deleted_at` + `recycle_expire_at`）

### 字段定义

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 文件条目ID |
| folder_id | INT UNSIGNED | INDEX | 所属文件夹ID |
| file_asset_id | INT UNSIGNED | - | 关联文件资产ID（实际存储的文件） |
| name | VARCHAR(255) | - | 文件名 |
| size | BIGINT | - | 文件大小（字节） |
| content_type | VARCHAR(128) | - | MIME类型 |
| is_avatar | TINYINT(1) | DEFAULT FALSE | 是否为头像文件 |
| is_active_avatar | TINYINT(1) | DEFAULT FALSE | 是否为当前使用的头像 |
| user_id | INT UNSIGNED | INDEX | 上传者用户ID |
| deleted_at | DATETIME | NULL, INDEX | 软删除时间（进入回收站时间） |
| recycle_expire_at | DATETIME | NULL, INDEX | 回收站过期时间（过期后物理删除） |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 索引

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| PRIMARY | 主键 | id | - |
| idx_sys_file_entries_folder_id | 普通 | folder_id | 按文件夹查询文件 |
| idx_sys_file_entries_user_id | 普通 | user_id | 按用户查询文件 |
| idx_sys_file_entries_deleted_at | 普通 | deleted_at | 软删除/回收站查询 |
| idx_sys_file_entries_recycle_expire_at | 普通 | recycle_expire_at | 回收站过期清理 |

### 关系

- 多对一：`sys_file_folders`（文件夹）
- 多对一：`sys_file_assets`（文件资产）
- 多对一：`sys_users`（上传者）
- 一对多：`sys_file_tag`（文件标签）

## 3. sys_file_assets 文件资产表

**说明**：文件物理存储映射表，实现秒传和去重。相同内容的文件只存储一份，通过引用计数管理生命周期。

**软删除**：否

### 字段定义

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 文件资产ID |
| file_hash | VARCHAR(255) | UNIQUE INDEX | 文件哈希值（用于秒传和去重） |
| object_key | VARCHAR(500) | - | 存储路径/对象键 |
| file_name | VARCHAR(255) | - | 原始文件名 |
| file_size | BIGINT | - | 文件大小（字节） |
| content_type | VARCHAR(128) | - | MIME类型 |
| storage_type | VARCHAR(32) | DEFAULT 'local' | 存储类型：local本地 / minio / oss / cos |
| ref_count | INT | DEFAULT 1 | 引用计数（为0时可安全删除物理文件） |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 索引

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| PRIMARY | 主键 | id | - |
| uniq_sys_file_assets_file_hash | 唯一 | file_hash | 文件哈希唯一（秒传核心） |

### 关系

- 一对多：`sys_file_entries`（文件条目）
- 一对一：`sys_media_assets`（媒体资产元数据）

### 秒传机制

1. 用户上传文件时，前端先计算文件哈希
2. 后端查询 `file_hash` 是否已存在
3. 若存在：直接创建 `file_entries` 记录，`ref_count++`，返回秒传成功
4. 若不存在：执行实际上传，创建 `file_assets` 记录

## 11. sys_upload_tasks 上传任务表

**说明**：分片上传任务表，管理大文件的分片上传流程，支持断点续传。

**软删除**：否

### 字段定义

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT UNSIGNED | PRIMARY KEY, AUTO_INCREMENT | 任务ID |
| upload_id | VARCHAR(128) | UNIQUE INDEX | 上传任务唯一标识（用于分片关联） |
| file_hash | VARCHAR(255) | INDEX | 文件哈希（用于秒传检测） |
| file_name | VARCHAR(255) | - | 原始文件名 |
| file_size | BIGINT | - | 文件总大小（字节） |
| content_type | VARCHAR(128) | - | MIME类型 |
| object_key | VARCHAR(500) | - | 最终存储路径/对象键 |
| storage_driver | VARCHAR(20) | DEFAULT 'minio' | 存储驱动 |
| total_parts | INT | - | 总分片数 |
| uploaded_parts | INT | DEFAULT 0 | 已上传分片数 |
| progress | INT | DEFAULT 0 | 上传进度（0-100） |
| status | VARCHAR(20) | DEFAULT 'uploading' | 状态：uploading上传中 / processing处理中 / completed已完成 / failed失败 / aborted已中止 |
| error_message | VARCHAR(500) | - | 失败原因 |
| user_id | INT UNSIGNED | INDEX | 上传者用户ID |
| folder_id | INT UNSIGNED | DEFAULT 0, INDEX | 目标文件夹ID |
| completed_at | DATETIME | NULL | 完成时间 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 索引

| 索引名 | 类型 | 字段 | 说明 |
|--------|------|------|------|
| PRIMARY | 主键 | id | - |
| uniq_sys_upload_tasks_upload_id | 唯一 | upload_id | 上传ID唯一 |
| idx_sys_upload_tasks_file_hash | 普通 | file_hash | 按文件哈希查询（秒传检测） |
| idx_sys_upload_tasks_user_id | 普通 | user_id | 按用户查询上传任务 |
| idx_sys_upload_tasks_folder_id | 普通 | folder_id | 按文件夹查询 |

### 关系

- 一对多：`sys_uploaded_parts`（上传分片）
- 多对一：`sys_users`（上传者）

### 上传流程

1. 前端计算文件哈希，请求创建上传任务
2. 后端检查 `file_hash` 是否已存在（秒传检测）
3. 若不存在：创建 `upload_task`，返回 `upload_id` 和分片预签名URL
4. 前端按分片上传，每片上传成功后回调记录 `uploaded_parts`
5. 全部上传完成后，前端请求合并，后端创建 `file_asset` 和 `file_entry`
