## 1. 安全设计原则

DevKit 后端系统遵循以下核心安全设计原则：

### 1.1 纵深防御（Defense in Depth）

系统采用多层安全控制，任何单一防线被突破后仍有后续保护：

```
请求 --> 网络层(CORS/安全头) --> 传输层(HTTPS) --> 应用层(JWT/RBAC/CSRF) --> 数据层(加密/哈希)
         |                      |                  |                       |
         +-- 限流               +-- Secure Cookie   +-- 验证码              +-- SQL注入防护
         +-- 安全头             +-- HSTS            +-- 风险评分            +-- 输入验证
```

### 1.2 最小权限原则（Least Privilege）

- **RBAC 权限模型**：User -> Role -> Permission，权限码精确到 `module:resource:action` 粒度
- **分层角色**：默认提供 `super`、`admin`、`user` 三级角色
- **组继承**：通过 Group -> Role 关联实现权限继承，支持递归父组查找
- **按需分配**：每个 API 端点通过 `middleware.Permission("code")` 独立校验

### 1.3 Fail-Closed 策略

当关键安全组件不可用时，系统默认拒绝请求而非放行：

| 场景 | 处理方式 |
|------|----------|
| Redis 不可用（Token 黑名单检查） | 拒绝请求，返回 401 |
| Redis 不可用（设备踢出检查） | 拒绝被踢设备访问 |
| JWT 签名算法不匹配 | 拒绝请求，返回 401 |
| 权限缓存加载失败 | 从数据库重新加载 |
| 风险评分 Redis 不可用 | 跳过评分（降级但不阻断） |

### 1.4 不泄露内部信息

- 错误响应统一格式，不暴露堆栈跟踪或内部路径
- 数据库错误不直接返回给客户端
- 密码字段序列化时排除（`json:"-"`）
- 安全日志中 IP 地址脱敏处理（最后一段掩码）

## 2. 安全层次模型

### 2.1 网络层

| 安全措施 | 实现方式 | 配置位置 |
|----------|----------|----------|
| CORS 白名单 | `config.yaml` 中 `cors.allow_origins` 配置允许的源 | `internal/middleware/cors.go` |
| 安全响应头 | SecurityHeaders 中间件自动注入 | `internal/middleware/security_headers.go` |
| HSTS | 生产环境通过反向代理启用 | Nginx/反向代理配置 |
| 预检缓存 | `cors.max_age` 配置（默认 12h） | `config.yaml` |

**CORS 安全校验**：当 `AllowCredentials=true` 时，代码强制拒绝通配符 `*` 源，防止服务器以不安全配置启动。

```go
// cors.go - 启动时安全校验
if cfg.AllowCredentials {
    for _, origin := range cfg.AllowOrigins {
        if origin == "*" {
            log.Fatal("AllowCredentials=true 时不允许使用通配符 * 作为 AllowOrigins")
        }
    }
}
```

### 2.2 传输层

| 安全措施 | 实现方式 |
|----------|----------|
| HTTPS | 生产环境通过反向代理（Nginx）配置 TLS |
| Secure Cookie | CSRF Token Cookie 设置 `SameSite=Lax` |
| Token 传输 | 支持 `Authorization: Bearer` 头、Cookie、Query 参数三种方式 |

### 2.3 应用层

| 安全措施 | 实现方式 | 详细文档 |
|----------|----------|----------|
| JWT 认证 | HS256 签名，Access + Refresh Token 对 | [02-认证授权安全.md](./02-认证授权安全.md) |
| RBAC 权限 | User -> Role -> Permission 三级模型 | [02-认证授权安全.md](./02-认证授权安全.md) |
| CSRF 防护 | Double Submit Cookie 模式 | [03-数据安全.md](./03-数据安全.md) |
| 限流 | 双层限流（全局 IP 令牌桶 + 数据库规则限流） | [04-网络安全.md](./04-网络安全.md) |
| 验证码 | 5 种类型，AES-GCM 加密答案，风险评分触发 | [02-认证授权安全.md](./02-认证授权安全.md) |
| 风险评分 | IP 维度积分累加，规则引擎自动评估 | [02-认证授权安全.md](./02-认证授权安全.md) |

### 2.4 数据层

| 安全措施 | 实现方式 | 详细文档 |
|----------|----------|----------|
| 身份证号加密 | AES-256-GCM 加密存储 | [03-数据安全.md](./03-数据安全.md) |
| 密码哈希 | bcrypt（cost factor 可配置） | [02-认证授权安全.md](./02-认证授权安全.md) |
| SQL 注入防护 | GORM 参数化查询 + LIKE 转义 | [03-数据安全.md](./03-数据安全.md) |
| 文件上传安全 | 扩展名白名单 + 黑名单 + Magic Bytes 交叉验证 | [03-数据安全.md](./03-数据安全.md) |

## 3. 中间件安全链

### 3.1 全局中间件链

所有请求按以下顺序经过全局中间件处理：

```
请求进入
  |
  v
[1] Logger             -- HTTP 请求日志（Zap）
  |
  v
[2] SecurityHeaders    -- 注入安全响应头
  |
  v
[3] CORS               -- 跨域资源共享控制
  |
  v
[4] RateLimiter        -- 全局 IP 令牌桶限流
  |
  v
[5] DBRateLimiter      -- 数据库规则路径限流
  |
  v
[6] CSRF               -- Double Submit Cookie 验证
  |
  v
[7] Recovery           -- Panic 恢复
  |
  v
  路由分发
```

### 3.2 认证路由附加中间件

需要认证的路由在全局链之后追加：

```
  路由分发
  |
  v
[8]  JWTAuth            -- JWT Token 验证 + 黑名单 + 设备踢出检查
  |
  v
[9]  SecurityLog        -- 写操作审计日志
  |
  v
[10] CaptchaGuard       -- 风险评分 + 验证码强制
  |
  v
[11] Permission         -- RBAC 权限校验（按路由配置）
  |
  v
  业务 Handler
```

### 3.3 中间件职责说明

| 顺序 | 中间件 | 文件 | 职责 |
|------|--------|------|------|
| 1 | Logger | `internal/middleware/logger.go` | 记录请求方法、路径、IP、状态码、延迟、User-Agent |
| 2 | SecurityHeaders | `internal/middleware/security_headers.go` | 注入 X-Content-Type-Options、X-Frame-Options 等安全头 |
| 3 | CORS | `internal/middleware/cors.go` | 校验 Origin 白名单，处理预检请求 |
| 4 | RateLimiter | `internal/middleware/ratelimit.go` | IP 维度令牌桶限流，10 分钟空闲清理 |
| 5 | DBRateLimiter | `internal/middleware/ratelimit_db.go` | 数据库驱动的路径匹配限流规则 |
| 6 | CSRF | `internal/middleware/csrf.go` | Double Submit Cookie 模式，安全方法豁免 |
| 7 | Recovery | gin 内置 | 捕获 panic，返回 500 |
| 8 | JWTAuth | `internal/middleware/auth.go` | 验证 Token 签名、黑名单、设备踢出状态 |
| 9 | SecurityLog | `internal/middleware/security_log.go` | 自动记录 POST/PUT/DELETE 操作到审计日志 |
| 10 | CaptchaGuard | `internal/middleware/captcha_guard.go` | 基于风险评分决定是否要求验证码 |
| 11 | Permission | `internal/middleware/permission.go` | 校验用户是否拥有所需权限码 |

## 4. 威胁模型

### 4.1 威胁与防护对照表

| 威胁类型 | 风险等级 | 防护措施 | 实现位置 |
|----------|----------|----------|----------|
| 暴力破解 | 高 | 登录失败计数 + 验证码触发 + 账户锁定 | `auth_service.go` |
| CSRF | 高 | Double Submit Cookie + 常量时间比较 + 移动端豁免 | `csrf.go` |
| XSS | 中 | CSP 头 + HTML 转义 + X-XSS-Protection | `security_headers.go` |
| SQL 注入 | 高 | GORM 参数化查询 + LIKE 转义 | `repository/escape.go` |
| 路径遍历 | 中 | `validateObjectKey` 拒绝 `..` 和绝对路径 | 文件服务 |
| Token 泄露 | 高 | Token 黑名单 + Refresh Token 轮换 + SHA-256 哈希存储 | `auth_service.go` |
| 重放攻击 | 中 | Refresh Token 原子化轮换 + 验证码一次性使用 | Lua 脚本 |
| 点击劫持 | 中 | X-Frame-Options: DENY | `security_headers.go` |
| MIME 嗅探 | 低 | X-Content-Type-Options: nosniff | `security_headers.go` |
| 信息泄露 | 中 | 错误信息脱敏 + IP 掩码 + 密码字段排除 | 全局 |
| 文件上传攻击 | 高 | 扩展名白名单 + 黑名单 + Magic Bytes 交叉验证 | `fileutil/validator.go` |
| 会话固定 | 中 | 登录时生成新 Token，旧 Token 失效 | `auth_service.go` |

### 4.2 暴力破解防护流程

```
登录请求
  |
  v
校验用户名/密码
  |
  +-- 失败 --> Redis INCR login_fail:ip:{ip}   (TTL 30min)
  |            Redis INCR login_fail:user:{user} (TTL 30min)
  |                |
  |                v
  |            失败次数 >= 阈值？
  |                |
  |           +----+----+
  |           |         |
  |          Yes        No
  |           |         |
  |           v         v
  |        返回验证码    返回登录失败
  |
  +-- 成功 --> 清除失败计数
              记录登录设备
              生成 Token 对
```

### 4.3 Token 安全防护流程

```
Token 请求
  |
  v
解析 JWT（强制 HS256）
  |
  v
SHA-256(Token) --> Redis 查询黑名单
  |
  +-- 在黑名单中 --> 拒绝（401）
  |
  +-- Redis 不可用 --> 拒绝（fail-closed）
  |
  +-- 不在黑名单 --> 检查设备踢出状态
                      |
                      +-- 已踢出 --> 拒绝（401）
                      |
                      +-- 正常 --> 放行
```

### 4.5 公开文件 API 安全防护

公开文件 API（`/files/:id/public-url`、`/files/batch-public-url`、`/share/:code/*`）是未认证端点，需要额外的安全控制：

#### 4.5.1 文件访问控制

| 接口 | 安全措施 | 说明 |
|------|----------|------|
| `GET /files/:id/public-url` | `is_public` 字段校验 | 仅返回 `is_public=true` 的文件 URL |
| `POST /files/batch-public-url` | `is_public` 校验 + 数量限制 | 最多 100 个 ID，防止批量枚举 |
| `GET /share/:code` | 128-bit 随机 code | 熵足够高，暴力破解不可行 |
| `POST /share/:code/verify` | bcrypt 密码校验 | 可选密码保护 |
| `GET /share/:code/file` | 分享状态 + 过期 + 访问次数 | 多重校验 |

#### 4.5.2 分享密码保护

分享功能支持可选的密码保护：

```
创建分享时可设置密码
     |
     v
密码经 bcrypt 哈希后存储（不可逆）
     |
     v
访问分享时：
  - hasPassword=false --> 直接访问
  - hasPassword=true  --> 需先调用 /share/:code/verify 验证密码
     |
     v
验证通过 --> 返回内容
验证失败 --> 返回错误
```

#### 4.5.3 原子化访问计数

分享访问计数使用 SQL 级别原子操作，防止高并发下超限：

```sql
UPDATE sys_file_shares
SET access_count = access_count + 1, accessed_at = NOW()
WHERE share_code = ? AND (max_access = 0 OR access_count < max_access)
```

#### 4.5.4 信息泄露防护

- 分享接口不再返回 `objectKey`（存储路径），防止基础设施信息泄露
- 文件预览接口使用临时 JWT Token（1 小时有效），绑定用户和文件 ID

## 5. 安全响应头

### 5.1 响应头一览

系统通过 `SecurityHeaders` 中间件在每个响应中注入以下安全头：

| 响应头 | 值 | 作用 | 防护威胁 |
|--------|-----|------|----------|
| `X-Content-Type-Options` | `nosniff` | 防止浏览器 MIME 类型嗅探 | MIME 嗅探攻击 |
| `X-Frame-Options` | `DENY` | 完全禁止页面被嵌入 iframe | 点击劫持 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 跨域请求仅发送源信息，同域发送完整路径 | 信息泄露 |
| `X-XSS-Protection` | `1; mode=block` | 启用浏览器 XSS 过滤器并阻止渲染 | 反射型 XSS |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; ...` | 限制资源加载来源 | XSS、数据注入 |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | 禁用敏感浏览器 API | 隐私泄露 |

### 5.2 CSP 策略详情

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  font-src 'self' data:;
```

| 指令 | 允许来源 | 说明 |
|------|----------|------|
| `default-src` | `'self'` | 默认只允许同源资源 |
| `script-src` | `'self'` | 仅允许同源脚本，禁止内联脚本 |
| `style-src` | `'self' 'unsafe-inline'` | 允许同源样式和内联样式（Ant Design Vue 需要） |
| `img-src` | `'self' data: https:` | 允许同源、data URL、HTTPS 图片 |
| `font-src` | `'self' data:` | 允许同源和 data URL 字体 |

### 5.3 HSTS 配置

开发环境中 HSTS 头已注释，生产环境应通过反向代理启用：

```nginx
# Nginx 配置
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

## 6. 安全审计日志

### 6.1 自动记录机制

`SecurityLogMiddleware` 自动捕获所有写操作（POST、PUT、DELETE），无需业务代码手动记录。

**记录内容**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `UserID` | uint | 操作用户 ID |
| `EventType` | varchar(30) | 事件类型（通过 PathToEventType 映射） |
| `EventDetail` | varchar(500) | 请求体摘要（限 64KB） |
| `IP` | varchar(50) | 客户端 IP |
| `UserAgent` | varchar(500) | 客户端 User-Agent |
| `Status` | tinyint | 0=失败，1=成功（根据响应状态码判断） |

### 6.2 事件类型映射

系统通过 `PathToEventType` 方法将 HTTP 方法 + 路径自动映射为事件类型：

| 方法 | 路径模式 | 事件类型 |
|------|----------|----------|
| POST | `/auth/login` | `login` |
| POST | `/auth/register` | `register` |
| POST | `/auth/logout` | `logout` |
| PUT | `/auth/password` | `password_change` |
| POST | `/auth/reset-password` | `password_reset` |
| POST | `/system/user` | `user_create` |
| PUT | `/system/user/*` | `user_update` |
| DELETE | `/system/user/*` | `user_delete` |
| POST | `/system/role` | `role_create` |
| PUT | `/system/role/*` | `role_update` |
| DELETE | `/system/role/*` | `role_delete` |
| POST | `/system/menu` | `menu_create` |
| PUT | `/system/menu/*` | `menu_update` |
| DELETE | `/system/menu/*` | `menu_delete` |
| POST | `/system/group` | `group_create` |
| PUT | `/system/group/*` | `group_update` |
| DELETE | `/system/group/*` | `group_delete` |

### 6.3 跳过记录的路径

以下路径不记录审计日志（避免冗余或性能影响）：

- `/api/v1/auth/*` -- 认证相关路径（登录/注册已有独立日志）
- `/api/v1/files/upload` -- 文件上传路径（请求体过大）

### 6.4 日志查询接口

| 接口 | 权限 | 说明 |
|------|------|------|
| `GET /auth/security-logs` | 已认证用户 | 查看自己的安全日志 |
| `GET /system/security-logs` | `security:log:view` | 管理员查看所有日志，支持多维筛选 |

## 7. 启动时安全校验

服务器启动时执行以下安全校验，防止以不安全配置运行：

```go
// cmd/server/main.go - validateSecrets()
func validateSecrets() {
    cfg := config.Get()

    // JWT_SECRET 不能为默认值
    if cfg.JWT.Secret == "" || cfg.JWT.Secret == "changeme" {
        log.Fatal("JWT_SECRET 未设置或为默认值，请通过环境变量设置")
    }

    // AES_KEY 不能为默认值
    if cfg.Crypto.AESKey == "" || cfg.Crypto.AESKey == "changeme" {
        log.Fatal("AES_KEY 未设置或为默认值，请通过环境变量设置")
    }

    // CAPTCHA_SECRET 不能为默认值
    if cfg.Captcha.Secret == "" || cfg.Captcha.Secret == "changeme" {
        log.Fatal("CAPTCHA_SECRET 未设置或为默认值，请通过环境变量设置")
    }
}
```

**必需的环境变量**：

| 环境变量 | 长度要求 | 用途 |
|----------|----------|------|
| `JWT_SECRET` | >= 64 字节 | JWT Token 签名密钥 |
| `AES_KEY` | 恰好 32 字节 | AES-256-GCM 数据加密密钥 |
| `CAPTCHA_SECRET` | 32 字节 | 验证码答案加密密钥 |
| `MYSQL_PASSWORD` | - | MySQL 数据库密码 |
| `REDIS_PASSWORD` | - | Redis 密码 |
