## 1. CORS 配置

### 1.1 基本配置

CORS（跨域资源共享）通过 `internal/middleware/cors.go` 中间件实现，基于 `github.com/gin-contrib/cors` 库。

配置来源：`config.yaml` 中的 `cors` 节。

| 配置项 | 说明 | 示例值 |
|--------|------|--------|
| `allow_origins` | 允许的源白名单 | `["http://localhost:5666"]` |
| `allow_methods` | 允许的 HTTP 方法 | `GET, POST, PUT, DELETE, PATCH, OPTIONS` |
| `allow_headers` | 允许的请求头 | `Authorization, Content-Type, X-CSRF-Token, ...` |
| `expose_headers` | 暴露给前端的响应头 | `Content-Length` |
| `allow_credentials` | 是否允许携带凭证 | `true` |
| `max_age` | 预检请求缓存时间 | `86400` |

### 1.2 AllowCredentials 安全校验

当 `AllowCredentials=true` 时，CORS 规范禁止使用通配符 `*` 作为 `AllowOrigins`。系统在启动时强制校验此规则：

```go
// internal/middleware/cors.go
func CORS(cfg config.CORSConfig) gin.HandlerFunc {
    // 安全校验：AllowCredentials=true 时禁止通配符
    if cfg.AllowCredentials {
        for _, origin := range cfg.AllowOrigins {
            if origin == "*" {
                log.Fatal("CORS 配置错误: AllowCredentials=true 时不允许 AllowOrigins 包含 '*'")
            }
        }
    }

    // 过滤空字符串
    origins := make([]string, 0, len(cfg.AllowOrigins))
    for _, o := range cfg.AllowOrigins {
        o = strings.TrimSpace(o)
        if o != "" {
            origins = append(origins, o)
        }
    }

    // 配置 CORS
    corsConfig := cors.Config{
        AllowOrigins:     origins,
        AllowMethods:     cfg.AllowMethods,
        AllowHeaders:     cfg.AllowHeaders,
        ExposeHeaders:    cfg.ExposeHeaders,
        AllowCredentials: cfg.AllowCredentials,
        MaxAge:           cfg.MaxAge,
    }

    return cors.New(corsConfig)
}
```

**安全效果**：防止服务器以不安全的 CORS 配置启动（`AllowCredentials=true` + `AllowOrigins=*` 会泄露用户凭证给任意网站）。

### 1.3 预检请求缓存

预检请求（OPTIONS）的缓存时间通过 `MaxAge` 配置，减少预检请求频率：

```yaml
cors:
  max_age: 86400  # 浏览器缓存预检结果（秒）
```

### 1.4 允许的请求头

系统配置了完整的允许请求头列表，包括自定义安全头：

```yaml
cors:
  allow_headers:
    - "Authorization"           # JWT Token
    - "Content-Type"            # 请求体类型
    - "X-CSRF-Token"            # CSRF Token
    - "X-Captcha-ID"            # 验证码 ID
    - "X-Captcha-Code"          # 验证码答案
    - "X-Captcha-Start-Time"    # 验证码开始时间
    - "X-Mobile-Token-Mode"     # 移动端 Token 模式标记
    - "X-Device-ID"             # 设备 ID
    - "X-Client-Type"           # 客户端类型（h5/app/miniapp）
    - "X-Refresh-Token"         # Refresh Token
```

## 2. 安全响应头

### 2.1 响应头一览

`SecurityHeaders` 中间件在每个 HTTP 响应中注入以下安全头：

| 响应头 | 值 | 防护威胁 |
|--------|-----|----------|
| `X-Content-Type-Options` | `nosniff` | MIME 类型嗅探攻击 |
| `X-Frame-Options` | `DENY` | 点击劫持（Clickjacking） |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Referrer 信息泄露 |
| `X-XSS-Protection` | `1; mode=block` | 反射型 XSS（旧版浏览器） |
| `Content-Security-Policy` | `default-src 'self'; ...` | XSS、数据注入、资源盗用 |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | 浏览器 API 滥用 |

### 2.2 X-Content-Type-Options: nosniff

阻止浏览器对响应体进行 MIME 类型嗅探。没有此头时，浏览器可能将 HTML 文件当作 JavaScript 执行。

```
场景：攻击者上传包含 <script> 标签的 .txt 文件
无此头：浏览器可能嗅探为 HTML 并执行脚本
有此头：浏览器严格按照 Content-Type 处理
```

### 2.3 X-Frame-Options: DENY

完全禁止页面被嵌入到 iframe 中，防止点击劫持攻击。

```
场景：攻击者将目标网站嵌入透明 iframe，诱导用户点击
DENY：浏览器拒绝渲染 iframe 中的页面
```

### 2.4 Referrer-Policy: strict-origin-when-cross-origin

| 场景 | 发送的 Referer |
|------|---------------|
| 同源请求 | 完整 URL |
| 跨域请求（HTTPS -> HTTPS） | 仅源（origin） |
| 降级请求（HTTPS -> HTTP） | 不发送 |

防止通过 Referer 头泄露 URL 中的敏感信息（如 Token、查询参数）。

### 2.5 Content-Security-Policy

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  font-src 'self' data:;
```

| 指令 | 允许来源 | 说明 |
|------|----------|------|
| `default-src` | `'self'` | 默认只允许同源 |
| `script-src` | `'self'` | 禁止内联脚本和外部脚本 |
| `style-src` | `'self' 'unsafe-inline'` | 允许内联样式（Ant Design Vue 需要） |
| `img-src` | `'self' data: https:` | 允许 data URL 和 HTTPS 图片 |
| `font-src` | `'self' data:` | 允许 data URL 字体 |

### 2.6 Permissions-Policy

禁用敏感的浏览器 API，防止恶意脚本滥用：

```
Permissions-Policy:
  camera=(),         -- 禁用摄像头
  microphone=(),     -- 禁用麦克风
  geolocation=()     -- 禁用地理位置
```

### 2.7 HSTS（HTTP Strict Transport Security）

开发环境中 HSTS 头已注释。生产环境应通过反向代理启用：

```nginx
# Nginx 配置
server {
    listen 443 ssl;

    # HSTS: 告诉浏览器未来 1 年内只使用 HTTPS 访问
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # 其他 SSL 配置...
}
```

**HSTS 参数说明**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `max-age` | 31536000 | 浏览器缓存 HSTS 策略 1 年（秒） |
| `includeSubDomains` | - | 策略应用于所有子域名 |
| `preload` | - | 可选，提交到浏览器 HSTS 预加载列表 |

## 3. 限流策略

### 3.1 双层限流架构

```
请求进入
  |
  v
[第 1 层] 全局 IP 令牌桶限流
  |
  +-- 超限 --> 返回 429
  |
  +-- 通过 --> [第 2 层] 数据库规则限流
                  |
                  +-- 匹配规则且超限 --> 返回 429 + 风险积分累加
                  |
                  +-- 通过 --> 继续处理
```

### 3.2 全局 IP 令牌桶限流

**算法**：令牌桶（Token Bucket），使用 `golang.org/x/time/rate` 实现。

**实现细节**：

```go
// internal/middleware/ratelimit.go
type ipLimiter struct {
    limiter  *rate.Limiter
    lastSeen time.Time
}

var (
    visitors = sync.Map{}  // map[string]*ipLimiter
    mu       sync.Mutex
)

func getVisitor(ip string) *rate.Limiter {
    if v, ok := visitors.Load(ip); ok {
        vl := v.(*ipLimiter)
        vl.lastSeen = time.Now()
        return vl.limiter
    }

    limiter := rate.NewLimiter(
        rate.Limit(config.RateLimit.Rate),  // 每秒令牌数
        config.RateLimit.Burst,             // 突发容量
    )
    visitors.Store(ip, &ipLimiter{limiter: limiter, lastSeen: time.Now()})
    return limiter
}
```

**配置参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `rate` | 100 | 每秒产生的令牌数 |
| `burst` | 200 | 令牌桶最大容量（突发请求上限） |

**清理机制**：后台 goroutine 每 5 分钟运行一次，清理 10 分钟内未活跃的 IP 限流器。

### 3.3 数据库规则限流

基于数据库 `sys_rate_limit_rules` 表的灵活规则引擎。

**规则模型**：

```go
// model/rate_limit_rule.go
type RateLimitRule struct {
    ID             uint    // 规则 ID
    PathPattern    string  // 路径模式，支持 * 通配符
    Method         string  // HTTP 方法: GET/POST/PUT/DELETE/*
    Rate           float64 // 每秒令牌数
    Burst          int     // 突发容量
    Cooldown       int     // 触发后冷却时间（秒）
    BlockDuration  int     // 封禁时长（秒）
    MaxViolations  int     // 最大违规次数（超过后封禁，0=不限制）
    ViolationScore int     // 违规风险积分
    Enabled        bool    // 是否启用
    Priority       int     // 优先级（越高越先匹配）
}
```

**路径匹配规则**：

| 模式 | 匹配示例 | 说明 |
|------|----------|------|
| `/api/v1/auth/*` | `/api/v1/auth/login` | 前缀匹配 |
| `*.js` | `/static/app.js` | 后缀匹配 |
| `/api/v1/system/user` | 仅精确路径 | 精确匹配 |
| `*` | 所有路径 | 通配符 |

**规则缓存**：使用 `atomic.Value` 实现无锁读取，每 30 秒从数据库自动刷新。

**违规处理流程**：

```
请求匹配规则
  |
  v
令牌桶检查
  |
  +-- 通过 --> 放行
  |
  +-- 超限 --> 违规计数 +1
                |
                v
              违规积分累加到风险评分系统
                |
                v
              设置 Retry-After 响应头
                |
                v
              返回 429 Too Many Requests
                |
                v
              违规次数 >= MaxViolations？
                |
           +----+----+
           |         |
          Yes        No
           |         |
           v         v
        封禁 IP     继续计数
        (BlockDuration)
```

### 3.4 限流响应

超限时返回标准的 429 响应：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 60
Content-Type: application/json

{
    "code": 429,
    "message": "请求过于频繁，请稍后再试"
}
```

### 3.5 风险积分联动

数据库规则限流触发时，违规积分自动累加到风险评分系统：

```go
// ratelimit_db.go - addRateLimitViolationScore()
func addRateLimitViolationScore(ctx context.Context, ip string, score int) {
    if score <= 0 {
        return
    }
    key := "risk:score:" + ip
    rdb.IncrBy(ctx, key, int64(score))
    rdb.Expire(ctx, key, 30*time.Minute)
}
```

## 4. WebSocket 安全

### 4.1 认证机制

WebSocket 连接通过 URL Query 参数传递 JWT Token 进行认证：

```
ws://example.com/api/v1/ws?token=<JWT_TOKEN>
```

**认证流程**：

```go
// router/router.go
// WebSocket 端点在公共路由组中，但内部自行验证 Token
r.GET("/ws", func(c *gin.Context) {
    token := c.Query("token")
    if token == "" {
        c.JSON(401, "缺少认证 Token")
        return
    }

    // 验证 JWT Token
    claims, err := jwt.Parse(token)
    if err != nil {
        c.JSON(401, "Token 无效")
        return
    }

    // 升级为 WebSocket 连接
    conn, _ := upgrader.Upgrade(c.Writer, c.Request, nil)
    hub.Register(claims.UserID, conn)
})
```

### 4.2 安全考虑

| 措施 | 说明 |
|------|------|
| Token 验证 | 连接时验证 JWT 签名和有效期 |
| Token 黑名单 | 已注销的 Token 无法建立连接 |
| 连接管理 | 服务端 Hub 管理所有连接，支持主动断开 |
| 心跳检测 | 定期检测连接活性，清理断开的连接 |

## 5. 文件预览安全

### 5.1 临时 Token 机制

文件预览使用独立的临时 Token，无需用户登录即可访问：

```
GET /api/v1/files/{id}/preview?token=<PREVIEW_TOKEN>
```

**Token 生成**：

```go
// pkg/jwt/jwt.go
func GeneratePreviewToken(userID uint, fileID string) (string, error) {
    claims := PreviewClaims{
        UserID: userID,
        FileID: fileID,
        RegisteredClaims: jwt.RegisteredClaims{
            ExpiresAt: jwt.NewNumericDate(time.Now().Add(1 * time.Hour)),
            IssuedAt:  jwt.NewNumericDate(time.Now()),
            Issuer:    "backend-server",
        },
    }

    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    return token.SignedString([]byte(config.Get().JWT.Secret))
}
```

### 5.2 安全特性

| 特性 | 说明 |
|------|------|
| 有效期 | 1 小时 |
| 绑定范围 | 绑定到特定用户 + 文件 |
| 签名算法 | HS256（与普通 JWT 一致） |
| 独立于 JWT | 不影响用户的 Access/Refresh Token |
| 用途限制 | 仅用于文件预览，不能用于其他 API |

### 5.3 使用场景

文件预览 Token 适用于以下场景：

- 分享文件预览链接（无需接收方登录）
- 嵌入式文件预览（iframe 中展示）
- 邮件中的文件预览链接
