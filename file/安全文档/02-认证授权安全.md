## 1. JWT 安全设计

### 1.1 签名算法

系统使用 **HS256**（HMAC-SHA256）作为 JWT 签名算法，并在解析时强制验证算法类型，防止 `alg:none` 攻击。

```go
// pkg/jwt/jwt.go
func Parse(tokenString string) (*Claims, error) {
    token, err := jwt.ParseWithClaims(tokenString, &Claims{}, func(token *jwt.Token) (interface{}, error) {
        // 强制验证签名算法为 HS256，防止 alg:none 攻击
        if _, ok := token.Method.(*jwt.SigningMethodHMAC); !ok {
            return nil, fmt.Errorf("unexpected signing method: %v", token.Header["alg"])
        }
        return []byte(config.Get().JWT.Secret), nil
    })
    // ...
}
```

### 1.2 Token 对结构

系统采用 Access Token + Refresh Token 双 Token 架构：

| Token 类型 | TTL | 包含信息 | 存储位置 |
|------------|-----|----------|----------|
| Access Token | 可配置（默认 168h） | UserID, Username, Roles | 客户端（Header/Cookie） |
| Refresh Token | 可配置（默认 720h） | 仅 UserID | Redis（SHA-256 哈希） |
| Preview Token | 1 小时 | UserID, FileID | URL Query 参数 |

```go
// Claims 结构
type Claims struct {
    UserID   uint     `json:"user_id"`
    Username string   `json:"username"`
    Roles    []string `json:"roles"`
    jwt.RegisteredClaims
}
```

**设计要点**：
- Access Token 包含用户基本信息，减少数据库查询
- Refresh Token 仅含 UserID，最小化泄露影响
- 两者使用不同的 TTL，Access Token 过期后可通过 Refresh Token 无感刷新

### 1.3 Token 轮换（Rotation）

每次使用 Refresh Token 刷新时，系统会生成全新的 Token 对，旧的 Refresh Token 立即失效。

**原子化实现**：使用 Redis Lua 脚本保证 READ-VERIFY-WRITE 操作的原子性，防止 TOCTOU 竞态条件。

```lua
-- auth_service.go - refreshTokenLuaScript
-- 返回值: -1=key不存在, 0=hash不匹配(重放), 1=成功
local key = KEYS[1]
local oldHash = ARGV[1]
local newHash = ARGV[2]
local ttl = tonumber(ARGV[3])

local stored = redis.call('GET', key)
if not stored then
    return -1  -- Token 已过期或不存在
end
if stored ~= oldHash then
    return 0   -- hash 不匹配，可能是重放攻击
end
redis.call('SETEX', key, ttl, newHash)
return 1       -- 成功，已原子性替换
```

**安全效果**：
- 并发刷新请求只有一个能成功，其余自动失败
- 旧 Refresh Token 立即失效，防止重放攻击
- Token 哈希存储，Redis 中不保存明文

### 1.4 Token 黑名单

用户注销或密码修改时，当前 Access Token 被加入黑名单。

**实现方式**：

```
Redis Key:    token_blacklist:{sha256(token)}
Redis Value:  "1"
TTL:          Token 剩余有效期
```

**校验流程**：

```go
// middleware/auth.go
tokenHash := sha256Hex(token)
blacklistKey := "token_blacklist:" + tokenHash

exists, err := rdb.Exists(ctx, blacklistKey).Result()
if err != nil {
    // Redis 不可用 -> fail-closed -> 拒绝请求
    c.JSON(500, "服务暂时不可用")
    c.Abort()
    return
}
if exists > 0 {
    // Token 已在黑名单中 -> 拒绝请求
    c.JSON(401, "Token 已失效")
    c.Abort()
    return
}
```

**Fail-Closed 策略**：Redis 不可用时拒绝请求，防止已注销的 Token 继续使用。

### 1.5 Refresh Token 存储

```
Redis Key:    refresh_token:{userID}
Redis Value:  sha256(refreshToken)  -- 存储哈希而非明文
TTL:          30 天（与 Refresh Token TTL 一致）
```

初始存储同样使用 Lua 脚本保证原子性：

```lua
-- storeRefreshTokenLuaScript
local key = KEYS[1]
local hash = ARGV[1]
local ttl = tonumber(ARGV[2])
redis.call('SETEX', key, ttl, hash)
return 1
```

## 2. 密码安全

### 2.1 bcrypt 哈希

系统使用 `golang.org/x/crypto/bcrypt` 进行密码哈希，cost factor 使用默认值 10（2^10 次迭代）。

```go
// 注册/修改密码时
hashedPassword, err := bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)

// 登录验证时
err := bcrypt.CompareHashAndPassword([]byte(user.Password), []byte(req.Password))
```

**bcrypt 特性**：
- 自带盐值（salt），每次哈希结果不同
- 抗彩虹表攻击
- 计算密集型，有效减缓暴力破解
- cost factor 可配置，适应硬件性能提升

### 2.2 密码策略

| 规则 | 要求 |
|------|------|
| 最小长度 | 6 字符 |
| 最大长度 | 128 字符 |
| 用户名校验 | 仅允许字母、数字、下划线、连字符 |

### 2.3 密码历史记录

系统记录用户最近 5 次密码的 bcrypt 哈希，防止重复使用旧密码。

```
数据库表: sys_password_history
字段:     user_id, password_hash, created_at
```

```go
// password_history_service.go
func (s *PasswordHistoryService) CheckRepeated(userID uint, newPassword string) (bool, error) {
    var histories []model.PasswordHistory
    // 查询最近 5 条记录
    db.Where("user_id = ?", userID).Order("created_at desc").Limit(5).Find(&histories)

    for _, h := range histories {
        if err := bcrypt.CompareHashAndPassword([]byte(h.PasswordHash), []byte(newPassword)); err == nil {
            return true, nil  // 密码重复
        }
    }
    return false, nil
}
```

### 2.4 登录失败锁定

系统通过 Redis 双维度追踪登录失败：

```
Redis Key 维度 1: login_fail:ip:{ip}        -- 按 IP 追踪
Redis Key 维度 2: login_fail:user:{username} -- 按用户名追踪
TTL:              30 分钟
```

**触发逻辑**：

```go
// auth_service.go
// 登录失败时
rdb.Incr(ctx, "login_fail:ip:"+ip)
rdb.Expire(ctx, "login_fail:ip:"+ip, 30*time.Minute)

rdb.Incr(ctx, "login_fail:user:"+username)
rdb.Expire(ctx, "login_fail:user:"+username, 30*time.Minute)

// 登录时检查
ipFailCount, _ := rdb.Get(ctx, "login_fail:ip:"+ip).Int()
userFailCount, _ := rdb.Get(ctx, "login_fail:user:"+username).Int()

if ipFailCount >= captchaLoginTrigger || userFailCount >= captchaLoginTrigger {
    // 要求输入验证码
}
```

### 2.5 强制修改密码

系统默认用户（vben、admin、jack）初始化时设置 `MustChangePassword: true`，首次登录必须修改密码。

```go
// auth_service.go - 登录后检查
if user.MustChangePassword {
    // 返回特殊状态码，前端跳转到修改密码页面
}
```

### 2.6 默认密码生成

当未通过环境变量设置默认用户密码时，系统自动生成密码：

```go

```

## 3. 验证码安全

### 3.1 验证码类型

系统支持 5 种验证码类型，触发时随机选择以防止机器人针对性破解：

| 类型 | 说明 | 验证方式 |
|------|------|----------|
| `numeric` | 数字验证码 | 精确匹配 |
| `slider` | 滑块验证码 | X 坐标容差 |
| `puzzle` | 拼图验证码 | X+Y 坐标容差 |
| `rotation` | 旋转验证码 | 角度容差 |
| `point` | 点选验证码 | 逐点坐标验证 |

### 3.2 答案加密存储

所有验证码答案在存储到 Redis 前使用 AES-GCM 加密：

```go
// pkg/captcha/captcha.go
func encryptAnswer(answer string, secret []byte) (string, error) {
    block, _ := aes.NewCipher(secret)
    gcm, _ := cipher.NewGCM(block)

    // 随机 nonce（crypto/rand）
    nonce := make([]byte, gcm.NonceSize())
    io.ReadFull(rand.Reader, nonce)

    // AES-GCM 加密 + 认证
    ciphertext := gcm.Seal(nonce, nonce, []byte(answer), nil)
    return base64.StdEncoding.EncodeToString(ciphertext), nil
}
```

**加密参数**：
- 算法：AES-256-GCM（认证加密，防篡改）
- 密钥：32 字节，通过 `CAPTCHA_SECRET` 环境变量设置
- Nonce：每次加密随机生成
- 存储：base64 编码后存入 Redis

### 3.3 一次性使用

验证码验证使用 Redis `GETDEL` 命令，原子性读取后立即删除，防止重放：

```go
// pkg/captcha/captcha.go
func (c *Captcha) Verify(id string, answer string) (bool, error) {
    // 原子性读取并删除
    encrypted, err := rdb.GetDel(ctx, "captcha:"+id).Result()
    if err != nil {
        return false, err  // 验证码不存在或已过期
    }

    // 解密答案
    expected, _ := decryptAnswer(encrypted, c.secret)

    // 比较答案（根据类型使用不同的容差策略）
    return c.verifyByType(expected, answer), nil
}
```

### 3.4 最小验证时间

验证码记录生成时间戳，验证时检查耗时是否低于人类极限：

```go
// 验证时检查
if elapsed < captchaConfig.MinDuration {  // 默认 500ms
    return false  // 机器人快速提交
}
```

### 3.5 答案容差配置

| 验证码类型 | 容差参数 | 默认值 |
|------------|----------|--------|
| slider | X 像素容差 | 可配置 |
| puzzle | X+Y 像素容差 | 可配置 |
| rotation | 角度容差 | 可配置 |
| point | 坐标像素容差 | 可配置 |

### 3.6 配置管理

验证码参数通过数据库 `sys_system_settings` 表管理（`group_key='captcha'`），支持运行时调整：

| 配置项 | 说明 |
|--------|------|
| `captcha_width` | 验证码图片宽度 |
| `captcha_height` | 验证码图片高度 |
| `captcha_length` | 数字验证码长度 |

## 4. 风险评分系统

### 4.1 架构概述

风险评分系统基于 IP 维度，通过 Redis 累加积分，实现自动化威胁检测。

```
请求进入
  |
  v
CaptchaGuard 中间件
  |
  v
检查路径是否在保护列表中
  |
  +-- 不在列表 --> 放行
  |
  +-- 在列表 --> 计算本次请求风险得分
                   |
                   v
                 Redis INCRBY 累加总分
                   |
                   v
                 总分 >= TriggerScore？
                   |
              +----+----+
              |         |
             Yes        No
              |         |
              v         v
          要求验证码    放行
              |
              v
          验证通过 --> 积分减半 + 白名单 10 分钟
```

### 4.2 风险规则

| 规则 | 默认得分 | 检测方式 | 说明 |
|------|----------|----------|------|
| `frequency` | +30 | Redis INCR，60 秒窗口 | 单 IP 请求频率异常（阈值 30 次/分钟） |
| `no_referer` | +20 | 检查 Referer 头 | 缺少 Referer 头 |
| `no_lang` | +15 | 检查 Accept-Language 头 | 缺少 Accept-Language 头 |
| `ua` | +25 | 关键词匹配 | User-Agent 含 curl/python/java/go-http/postman/scrapy |
| `interval` | +20 | Redis Sorted Set 滑动窗口 | 请求间隔过短（500 次/10 秒） |

### 4.3 积分累加

使用 Redis `INCRBY` 原子操作累加积分，同时重置 TTL：

```go
// captcha_guard.go - accumulateRiskScore()
func accumulateRiskScore(ctx context.Context, ip string, score int, decayMinutes int) (int, error) {
    key := "risk:score:" + ip

    // 原子性累加
    total, err := rdb.IncrBy(ctx, key, int64(score)).Result()

    // 重置 TTL（衰减窗口）
    rdb.Expire(ctx, key, time.Duration(decayMinutes)*time.Minute)

    return int(total), nil
}
```

### 4.4 积分衰减

积分 TTL 过期后自动清零。验证码通过后，积分减半（而非清零）：

```lua
-- halveScript - 原子性减半
local key = KEYS[1]
local val = tonumber(redis.call('GET', key) or "0")
if val <= 0 then
    redis.call('DEL', key)
    return 0
end
local newVal = math.floor(val / 2)
if newVal <= 0 then
    redis.call('DEL', key)
    return 0
end
local ttl = redis.call('PTTL', key)
redis.call('SET', key, newVal)
if ttl > 0 then
    redis.call('PEXPIRE', key, ttl)
end
return newVal
```

### 4.5 触发阈值

| 阈值 | 默认值 | 行为 |
|------|--------|------|
| `TriggerScore` | 50 | 达到此分数要求验证码 |
| `BlockScore` | 80 | 达到此分数直接拒绝请求 |
| `DecayMinutes` | 30 | 积分衰减周期（分钟） |
| `DecayRate` | 0.5 | 衰减率 |

### 4.6 保护路径

默认受风险评分保护的路径：

```
/api/v1/system/user

```

## 5. 设备管理

### 5.1 设备 ID 识别

```go
// middleware/auth.go
func getDeviceID(c *gin.Context) string {
    // 优先使用前端传递的 X-Device-ID
    if id := c.GetHeader("X-Device-ID"); id != "" {
        return id
    }
    // 降级方案：SHA-256(UserAgent + IP) 前 16 位
    ua := c.GetHeader("User-Agent")
    ip := c.ClientIP()
    hash := sha256.Sum256([]byte(ua + ip))
    return fmt.Sprintf("web-%x", hash[:8])
}
```

## 6. RBAC 权限模型

### 6.1 模型结构

```
User --(多对多)--> Role --(多对多)--> Permission
  |                    ^
  |                    |
  +--(多对多)--> Group --(多对多)--+
                  |
                  +--(自引用)--> Parent Group
```

### 6.2 权限码规范

权限码格式：`module:resource:action`

| 模块 | 资源 | 操作 | 权限码示例 |
|------|------|------|------------|
| system | user | view/add/edit/delete | `system:user:view` |
| system | role | view/add/edit/delete | `system:role:view` |
| system | menu | view/add/edit/delete | `system:menu:view` |
| system | group | view/add/edit/delete | `system:group:view` |
| system | setting | list/edit | `system:setting:list` |
| system | task | view/edit/delete/run | `system:task:view` |
| system | notification | view/publish | `system:notification:view` |
| security | log | view | `security:log:view` |
| security | risk | view/edit | `security:risk:view` |
| security | ratelimit | view/edit/delete | `security:ratelimit:view` |
| security | realname | view/approve/reject | `security:realname:view` |

| question | create/edit/delete/publish | - | `question:create` |

### 6.3 权限解析流程

```go
// auth_service.go - loadPermissionCodesFromDB()
func (s *AuthService) loadPermissionCodesFromDB(userID uint) ([]string, error) {
    permissionSet := make(map[string]struct{})

    // 1. 获取用户直接关联的角色
    directRoleIDs := getUserRoleIDs(userID)

    // 2. 递归获取用户所在组的角色
    groupRoleIDs := getGroupRoleIDsRecursive(user.GroupID)

    // 3. 合并去重
    allRoleIDs := merge(directRoleIDs, groupRoleIDs)

    // 4. 批量加载角色（避免 N+1 查询）
    roles := batchGetRoles(allRoleIDs)

    // 5. 解析每个角色的 Permissions JSON 数组
    for _, role := range roles {
        var perms []string
        json.Unmarshal([]byte(role.Permissions), &perms)
        for _, p := range perms {
            permissionSet[p] = struct{}{}
        }
    }

    return keys(permissionSet), nil
}
```

### 6.4 权限缓存

- 缓存位置：Redis
- 缓存 Key：`permission_codes:{userID}`
- TTL：10 分钟
- 失效时机：角色变更、用户角色绑定变更时主动失效

```go
// 缓存失效
s.InvalidatePermissionCache(userID)
s.InvalidatePermissionCacheForUsers(userIDs)  // 批量失效
```

### 6.5 权限中间件

```go
// middleware/permission.go
func Permission(requiredCode string) gin.HandlerFunc {
    return func(c *gin.Context) {
        userID := c.GetUint("user_id")

        // 加载用户权限码（带缓存）
        codes, err := authService.GetPermissionCodes(userID)

        // 精确匹配
        for _, code := range codes {
            if code == requiredCode {
                c.Next()
                return
            }
        }

        c.JSON(403, gin.H{"message": "权限不足"})
        c.Abort()
    }
}
```

|------|------|----------|
| `super` | 超级管理员，拥有所有权限 | vben |

| `user` | 普通用户，基础权限 | jack |

所有默认用户初始化时设置 `MustChangePassword: true`，首次登录必须修改密码。
