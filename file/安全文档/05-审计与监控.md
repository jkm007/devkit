## 1. 安全日志系统

### 1.1 自动记录机制

`SecurityLogMiddleware` 自动捕获所有写操作（POST、PUT、DELETE），无需业务代码手动记录。

**工作流程**：

```
写操作请求进入（POST/PUT/DELETE）
  |
  v
跳过路径检查
  |
  +-- /api/v1/auth/*       --> 跳过（已有独立登录日志）
  +-- /api/v1/files/upload --> 跳过（请求体过大）
  |
  v
包装 ResponseWriter（捕获状态码）
  |
  v
读取请求体（限 64KB）
  |
  v
调用下游 Handler
  |
  v
PathToEventType 映射事件类型
  |
  v
写入 sys_security_logs 表
```

### 1.2 日志字段

| 字段 | 类型 | 长度 | 说明 |
|------|------|------|------|
| `id` | uint | - | 主键 |
| `user_id` | uint | - | 操作用户 ID |
| `username` | varchar | 50 | 用户名（只读，JOIN 查询） |
| `event_type` | varchar | 30 | 事件类型 |
| `event_detail` | varchar | 500 | 请求体摘要 |
| `ip` | varchar | 50 | 客户端 IP（脱敏） |
| `user_agent` | varchar | 500 | 客户端 User-Agent |
| `status` | tinyint | - | 0=失败，1=成功 |
| `created_at` | datetime | - | 记录时间 |

```
- end_time: 结束时间
```

### 1.5 补充的登录日志

除 `SecurityLogMiddleware` 自动记录外，登录操作还有独立的详细日志：

**Redis 登录失败追踪**：

```
Redis Key 1: login_fail:ip:{ip}          -- 按 IP 统计
Redis Key 2: login_fail:user:{username}  -- 按用户名统计
TTL:         30 分钟
```

**用途**：
- 触发登录验证码（失败次数 >= 阈值时）
- 暴力破解检测
- 异常登录分析

## 2. 登录设备追踪

### 2.1 设备信息记录

每次登录成功后，系统记录完整的设备信息到 `sys_login_devices` 表。

**设备模型字段**：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `device_id` | varchar | 设备唯一标识 | `web-a1b2c3d4e5f6` |
| `device_type` | varchar | 设备类型 | `web` / `h5` / `app` / `miniapp` |
| `device_name` | varchar | 设备名称 | iPhone 15 |
| `browser` | varchar | 浏览器（UA 解析） | Chrome 120 |
| `os` | varchar | 操作系统（UA 解析） | macOS 14.2 |
| `ip` | varchar | 登录 IP | 192.168.1.100 |
| `location` | varchar | 登录位置 | - |
| `app_version` | varchar | 应用版本 | 1.0.0 |
| `system_version` | varchar | 系统版本 | iOS 17.2 |
| `device_model` | varchar | 设备型号 | iPhone15,2 |
| `platform` | varchar | 平台 | iOS / Android |
| `channel` | varchar | 渠道 | AppStore / GooglePlay |
| `token_jti` | varchar | JWT Token ID | - |
| `last_active_at` | datetime | 最后活跃时间 | - |
| `is_current` | tinyint | 是否当前设备 | 0 / 1 |

### 2.2 设备 ID 生成

```go
// middleware/auth.go
func getDeviceID(c *gin.Context) string {
    // 优先使用前端传递的 X-Device-ID
    if id := c.GetHeader("X-Device-ID"); id != "" {
        return id
    }

    // 降级方案：基于 User-Agent + IP 生成
    ua := c.GetHeader("User-Agent")
    ip := c.ClientIP()
    hash := sha256.Sum256([]byte(ua + ip))
    return fmt.Sprintf("web-%x", hash[:8])
}
```

### 2.3 最后活跃时间更新

每次认证请求时更新设备的最后活跃时间：

```go
// 认证成功后
db.Model(&LoginDevice{}).
    Where("user_id = ? AND device_id = ?", userID, deviceID).
    Update("last_active_at", time.Now())
```

### 2.4 设备管理接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/auth/devices` | GET | 查看当前用户的所有登录设备 |
| `/auth/devices/:id` | DELETE | 踢出指定设备 |
| `/auth/devices/others` | DELETE | 踢出除当前设备外的所有设备 |

**踢出实现**：

```go
// login_device_service.go
func (s *LoginDeviceService) KickDevice(userID, deviceID uint) error {
    // 1. 验证设备属于当前用户
    var device LoginDevice
    db.Where("id = ? AND user_id = ?", deviceID, userID).First(&device)
    if device.ID == 0 {
        return errors.New("设备不存在")
    }

    // 2. 防止踢出当前设备
    if device.IsCurrent {
        return errors.New("不能踢出当前设备")
    }

    // 3. Redis 标记被踢设备（24 小时 TTL）
    kickKey := fmt.Sprintf("kicked_device:%d:%s", userID, device.DeviceID)
    rdb.Set(ctx, kickKey, "1", 24*time.Hour)

    // 4. 删除设备记录
    db.Delete(&device)

    return nil
}
```

## 3. 风险评分监控

```

Authorization: Bearer <token>
权限码: security:risk:view

Response:
{
    "data": [
        {
            "ip": "192.168.1.***",
            "score": 75,
            "ttl": 1800
        }
    ]
}
```

### 3.2 单 IP 评分查询

```
GET /api/v1/system/risk/score?ip=192.168.1.100
Authorization: Bearer <token>
权限码: security:risk:view

Response:
{
    "ip": "192.168.1.***",
    "score": 75,
    "ttl": 1800
}
```

### 3.3 评分统计

```
GET /api/v1/system/risk/stats

权限码: security:risk:view

Response:
{
    "total_ips": 150,
    "high_risk_count": 5,
    "medium_risk_count": 20,
    "low_risk_count": 125

```

### 3.4 手动清除评分

```
DELETE /api/v1/system/risk/clear?ip=192.168.1.100
Authorization: Bearer <token>
权限码: security:risk:edit

Response:
{
    "message": "评分已清除"
}
```

### 3.5 风险评分规则

| 规则 | 默认得分 | 检测逻辑 |
|------|----------|----------|
| `frequency` | +30 | 60 秒内请求超过 30 次 |
| `no_referer` | +20 | 请求缺少 Referer 头 |
| `no_lang` | +15 | 请求缺少 Accept-Language 头 |
| `ua` | +25 | User-Agent 含可疑关键词 |
| `interval` | +20 | 10 秒内请求超过 500 次 |

### 3.6 风险评分生命周期

```
请求触发风险规则
  |
  v
Redis INCRBY 累加积分（risk:score:{ip}）
  |
  v
设置/重置 TTL（默认 30 分钟）
  |
  v
积分持续累加
  |
  v
达到 TriggerScore（50）--> 要求验证码
  |
  v
验证码通过 --> 积分减半 + 白名单 10 分钟
  |
  v
TTL 过期 --> 积分自动清零
```

## 4. 限流违规追踪

### 4.1 违规次数累加

每次限流规则触发时，违规计数器递增：

```go
// ratelimit_db.go
type ipState struct {
    limiter      *rate.Limiter
    violations   atomic.Int64   // 违规计数
    blockedUntil atomic.Int64   // 封禁截止时间
    cooldownEnd  atomic.Int64   // 冷却截止时间
}

// 触发限流时
state.violations.Add(1)
```

### 4.2 违规积分累加

限流违规时自动累加风险积分：

```go
// ratelimit_db.go - addRateLimitViolationScore()
func addRateLimitViolationScore(ctx context.Context, ip string, score int) {
    if score <= 0 {
        return
    }
    key := "risk:score:" + ip
    rdb.IncrBy(ctx, key, int64(score))
    rdb.Expire(ctx, key, 30*time.Minute)
}
```

### 4.3 最大违规后封禁

当违规次数超过 `MaxViolations` 阈值时，IP 被封禁 `BlockDuration` 秒：

```go
// rate_limit_rule_service.go - MatchAndCheck()
if rule.MaxViolations > 0 && state.violations.Load() >= int64(rule.MaxViolations) {
    // CAS 操作，防止多个 goroutine 同时触发封禁
    if state.blockedUntil.CompareAndSwap(0, time.Now().Add(time.Duration(rule.BlockDuration)*time.Second).Unix()) {
        state.violations.Store(0)  // 重置计数
    }
}
```

### 4.4 封禁状态检查

```
请求进入
  |
  v
检查 blockedUntil
  |
  +-- 当前时间 < blockedUntil --> 拒绝（429）
  |
  +-- 当前时间 >= blockedUntil --> 解除封禁，继续检查
```

## 5. OAuth 安全

### 5.1 state 参数防 CSRF

OAuth 授权流程中使用 `state` 参数防止 CSRF 攻击：

```
用户点击 "GitHub 登录"
  |
  v
生成随机 state --> 存入 Redis（TTL 5 分钟）
  |
  v
重定向到 GitHub 授权页（携带 state）
  |
  v
用户授权后回调（携带 code + state）
  |
  v
校验 state 是否与 Redis 中的一致
  |
  +-- 不一致 --> 拒绝（CSRF 攻击）
  |
  +-- 一致 --> 使用 code 换取 AccessToken
```

### 5.2 AccessToken 加密存储

OAuth AccessToken 和 RefreshToken 使用 AES-256-GCM 加密后存储：

```
数据库表: sys_oauth_users
加密字段: access_token, refresh_token
存储格式: base64(nonce + ciphertext + auth_tag)
```

### 5.3 绑定/解绑管理

| 操作 | 接口 | 说明 |
|------|------|------|
| 绑定 | `POST /auth/oauth/{provider}/bind` | 将第三方账号绑定到当前用户 |
| 解绑 | `DELETE /auth/oauth/{provider}/unbind` | 解除第三方账号绑定 |
| 查询 | `GET /auth/oauth/bindings` | 查看已绑定的第三方账号 |

**安全措施**：
- 绑定时验证第三方账号未被其他用户绑定
- 解绑时检查用户是否有其他登录方式（防止账户锁定）
- AccessToken 使用 AES-GCM 加密存储

## 6. 定时任务安全

### 6.1 任务执行状态记录

定时任务系统记录每次执行的详细状态：

| 字段 | 说明 |
|------|------|
| 任务名称 | 任务标识 |
| 执行时间 | 开始和结束时间 |
| 执行状态 | 成功/失败/超时 |
| 执行结果 | 结果摘要或错误信息 |
| 触发方式 | 自动/手动 |

### 6.2 手动触发权限控制

手动触发定时任务需要 `system:task:run` 权限码：

```go
// router/router.go
authorized.POST("/system/scheduled-tasks/:id/run",
    middleware.Permission("system:task:run"),
    scheduledTaskHandler.RunTask,
)
```

**权限矩阵**：

| 权限码 | 操作 | 说明 |
|--------|------|------|
| `system:task:view` | 查看任务列表 | 只读 |
| `system:task:edit` | 编辑任务配置 | 修改执行规则 |
| `system:task:delete` | 删除任务 | 移除定时任务 |
| `system:task:run` | 手动触发执行 | 立即执行一次 |

### 6.3 任务安全考虑

| 措施 | 说明 |
|------|------|
| 权限控制 | 仅管理员可查看、编辑、触发任务 |
| 审计日志 | 任务编辑和触发记录到安全日志 |
| 执行隔离 | 任务在独立 goroutine 中执行，不影响主服务 |
| 超时控制 | 任务执行有超时限制，防止无限运行 |
| 错误处理 | 任务失败记录错误日志，不影响其他任务 |
