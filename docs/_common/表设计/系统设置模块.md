# 系统设置模块表设计

> 对应功能：系统配置的运行时管理，支持通过后台界面修改配置而无需重启服务。

---

## sys_system_settings — 系统配置表

存储所有可运行时修改的系统配置项，采用 key-value 结构，按分组归类。

```sql
CREATE TABLE IF NOT EXISTS `sys_system_settings` (
    `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `group_key`   VARCHAR(50)  NOT NULL COMMENT '分组标识',
    `key`         VARCHAR(100) NOT NULL COMMENT '配置键',
    `value`       TEXT         DEFAULT NULL COMMENT '配置值(JSON格式)',
    `label`       VARCHAR(100) NOT NULL COMMENT '配置名称（前端展示）',
    `type`        VARCHAR(20)  NOT NULL DEFAULT 'string' COMMENT '值类型: string/number/boolean/json/select',
    `options`     TEXT         DEFAULT NULL COMMENT '可选项(JSON数组，type=select时使用)',
    `tip`         VARCHAR(500) DEFAULT '' COMMENT '配置说明/提示文字',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序',
    `is_public`   TINYINT      NOT NULL DEFAULT 0 COMMENT '是否前端公开可见: 0否 1是',
    `is_sensitive` TINYINT     NOT NULL DEFAULT 0 COMMENT '是否敏感字段: 0否 1是（返回时脱敏）',
    `updated_by`  BIGINT UNSIGNED DEFAULT NULL COMMENT '最后修改人ID',
    `created_at`  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    `updated_at`  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_group_key` (`group_key`, `key`),
    KEY `idx_group_key` (`group_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='系统配置表';
```

### 字段说明

| 字段 | 说明 |
|------|------|
| `group_key` | 配置分组，如 `basic`、`email`、`sms`、`captcha`、`storage`、`wechat`、`security` |
| `key` | 配置键，如 `site_name`、`smtp_host`，同一分组内唯一 |
| `value` | JSON 格式的配置值。字符串 `'"abc"'`、数字 `'123'`、布尔 `'true'`/`'false'`、数组/对象 `'["a","b"]'` |
| `label` | 前端表单展示的中文名称 |
| `type` | 决定前端渲染的表单组件类型 |
| `options` | type=select 时的可选值，如 `[{"label":"阿里云","value":"aliyun"}]` |
| `is_public` | 为 1 时前端可通过公开接口获取（如站点名称、验证码开关等） |
| `is_sensitive` | 为 1 时返回脱敏（非空返回 `"******"`，空返回 `""`），提交 `"******"` 则跳过更新 |
| `updated_by` | 最后修改人的用户 ID，用于审计 |

### value 存储规范

| 类型 | 存储格式 | 示例 |
|------|---------|------|
| string | JSON 字符串 | `'"管理系统"'` |
| number | JSON 数字 | `'465'` |
| boolean | JSON 布尔 | `'true'` / `'false'` |
| json | JSON 数组或对象 | `'["jpg","png"]'` |
| select | JSON 字符串（value 值） | `'"aliyun"'` |

## 配置逻辑说明

### captcha_enabled 与 captcha_login_trigger 的关系

| captcha_enabled | captcha_login_trigger | 行为 |
|----------------|----------------------|------|
| `false` | 任意值 | **不显示验证码**，即使登录失败 |
| `true` | `0` | **始终显示验证码** |
| `true` | `3` | 前 2 次登录不显示，第 3 次失败后开始显示 |

**前端逻辑**：
```
if (!captcha_enabled) → 不渲染验证码
if (captcha_login_trigger === 0) → 始终渲染
if (login_fail_count >= captcha_login_trigger) → 渲染验证码
```

### session_timeout 与 JWT TTL 的关系

| 配置 | 来源 | 说明 |
|------|------|------|
| `jwt.access_ttl` | config.yaml | AccessToken 有效期（如 168h），Token 过期后必须刷新 |
| `security.session_timeout` | sys_system_settings | 无操作超时时间，用于前端自动登出提示 |

两者独立生效：
- `session_timeout` 控制前端：用户无操作 N 分钟后，前端提示"会话超时"并调用登出
- `access_ttl` 控制后端：Token 过期后后端返回 401，前端自动刷新

**建议**：`session_timeout` 应小于 `access_ttl`，避免 Token 还有效但用户已被前端踢出。

### 存储配置与 driver 的关系

不同 driver 使用不同的配置项：

| driver | 使用的配置项 |
|--------|------------|
| `local` | storage_max_size, storage_allowed_ext |
| `minio` | storage_max_size, storage_allowed_ext, minio_* |
| `oss` | storage_max_size, storage_allowed_ext, oss_* |
| `cos` | storage_max_size, storage_allowed_ext, cos_* |

## 配置分组说明

| group_key | 说明 | 敏感字段 | 前端可见 |
|-----------|------|---------|---------|
| `basic` | 基础站点信息 | 无 | ✅ 全部可见 |
| `email` | 邮箱 SMTP 配置 | smtp_password | ❌ |
| `sms` | 短信服务配置 | sms_secret_key | ❌ |
| `captcha` | 验证码配置 | 无 | ✅ 部分可见 |
| `storage` | 文件存储配置 | minio_secret_key, oss_secret_key, cos_secret_key | ❌ |
| `wechat` | 微信生态配置 | wechat_miniapp_secret, wechat_official_secret | ❌ |
| `security` | 安全策略配置 | 无 | ❌ |
