# 题库管理系统设计

## 1. 设计目标

题库管理模块必须和当前 DevKit 的系统能力统一，不单独重复建设上传、预览、分享、分组、权限等通用能力。

核心原则：

- **题目是业务内容**：题干、选项、答案、解析、材料题内容都属于题库业务数据。
- **图片、文档、音频、视频是文件资产**：所有文件先进入文件管理，再由题库通过 `fileId` 关联。
- **导入源文件必须保留**：Excel、Word、PDF、附件包等导入文件统一保存到文件管理，导入任务只记录引用。
- **发布后才进入可解析状态**：题目发布后生成版本快照，用户端才能练习、考试、查看解析。
- **解析也支持富媒体**：答案解析不是纯文本，解析内容可以插入图片、音频、视频、文档附件。
- **分组承载班级能力**：当前系统没有独立班级表，班级/学习组/组织班统一先使用 `sys_groups`。
- **接口统一带 `/api/v1` 前缀**：本文所有接口路径均按实际路由风格写完整前缀。
- **题库业务表统一使用 `qb_` 前缀**：系统管理表继续使用 `sys_`，题库业务表统一使用 question bank 缩写 `qb_`。

## 2. 与当前系统能力的关系

### 2.1 已有能力映射

| 业务需求 | 当前系统已有模块 | 复用方式 |
|---|---|---|
| 上传导入 Excel/Word/PDF/附件包 | 文件上传、分片上传、秒传 | 先调用 `/api/v1/files/upload/*` 完成上传，再创建题库导入任务 |
| 题干图片/选项图片/解析图片 | 文件管理 `sys_file_entries` / `sys_file_assets` | 题库表只保存 `fileId` 和用途，不保存二进制 |
| 题干音频/解析音频 | 媒体资产 `sys_media_assets` | 复用音频元数据、在线播放、下载权限 |
| 题干视频/解析视频 | 媒体资产 `sys_media_assets` | 复用视频元数据、HLS 转码、在线播放 |
| 材料文档/解析文档 | 文件管理 | 作为题目附件，支持预览或下载 |
| 文件分类和标签 | 文件夹、标签、文件类型规则 | 题库导入文件、题目附件进入固定业务目录并可自动打标签 |
| 分享给班级 | 系统分组 `sys_groups` | 班级先视为分组，题目发布范围绑定 `groupId` |
| 部分人可见 | 用户、分组、角色 | 通过题目可见范围控制 `public/group/user/role` |
| 题目链接分享 | 文件分享设计可参考 | 题目分享独立建表，记录题目版本、有效期、访问次数 |

### 2.2 表名前缀规范

| 模块 | 表前缀 | 示例 |
|---|---|---|
| 系统管理 | `sys_` | `sys_users`、`sys_groups`、`sys_file_entries` |
| 题库管理 | `qb_` | `qb_questions`、`qb_question_versions`、`qb_question_attachments` |
| 后续考试管理 | 建议 `exam_` | `exam_papers`、`exam_records` |
| 后续学习/练习 | 建议 `study_` | `study_favorites`、`study_wrong_questions` |

题库模块可以引用 `sys_*` 表，但题库自身新增表不再使用无前缀的 `questions`、`question_versions` 这类名称。

## 3. 题目模型设计

### 3.1 题目资源类型

| 类型 | 标识 | 说明 | 默认可见范围 |
|---|---|---|---|
| 公共题目 | `public` | 平台公共题库题目 | 发布后所有有权限用户可见 |
| 私有题目 | `private` | 个人创建、个人维护 | 仅创建人可见 |
| 分组题目 | `group` | 发布/分享给指定分组 | 指定分组成员可见 |
| 指定用户题目 | `user` | 只授权给部分用户 | 指定用户可见 |

> 当前系统没有独立“班级”表，所以“分享到班级”统一设计为“分享到分组”。后续如果新增班级模块，可让班级表关联 `sys_groups.id`，题库授权层无需重构。

### 3.2 题目状态

| 状态 | 标识 | 说明 | 是否可解析 | 是否可练习/考试 |
|---|---|---|---|---|
| 草稿 | `draft` | 录入中，未发布 | 否 | 否 |
| 待审核 | `pending` | 提交公共发布或敏感内容待审核 | 否 | 否 |
| 已驳回 | `rejected` | 审核不通过 | 否 | 否 |
| 已发布 | `published` | 内容已确认，生成发布快照 | 是 | 是，取决于可见范围 |
| 已下架 | `archived` | 暂停用户端使用 | 否 | 否 |
| 已删除 | `deleted` | 软删除 | 否 | 否 |

“发布了就相当于分析了”的具体含义：

1. 发布时校验题干、内容、答案、解析、附件、媒体状态。
2. 发布成功后生成 `qb_question_versions` 快照。
3. 用户端只读取发布版本，不直接读取编辑态。
4. 已发布版本可以用于练习、考试、错题、收藏、统计和解析展示。
5. 后续编辑不会影响历史发布版本；再次发布生成新版本。

### 3.3 可见范围

题目状态决定“能不能使用”，可见范围决定“谁能使用”。

| scope_type | scope_id | 说明 |
|---|---:|---|
| `public` | 0 | 全部登录用户可见，仍受接口权限控制 |
| `group` | group_id | 指定分组可见，可配置是否包含子分组 |
| `user` | user_id | 指定用户可见 |
| `role` | role_id | 指定角色可见 |

推荐规则：

- 私有题目发布后默认仍然只有创建人可见。
- 分享到班级/分组时写入 `scope_type=group`。
- 公共题库发布写入 `scope_type=public`。
- 用户端题目列表只返回 `published` 且用户命中可见范围的题目。

## 4. 题型与富媒体内容设计

本系统面向所有考试练习用户，不只服务某一种考试。因此题型设计要覆盖通用考试、资格认证、语言考试、学历考试、职业技能考试、面试刷题、编程练习等场景。

### 4.2 题目内容分区

题目不是只有一个 `content` 字段，前端编辑器应按分区组织：

| 分区 | 字段 | 说明 | 富媒体能力 |
|---|---|---|---|
| 题干 | `stem` | 用户看到的题目描述 | 支持文字中间插入图片、视频、音频、公式、代码、表格、文档引用 |
| 题目内容 | `content` | 题型结构，如选项、填空、子题、排序项、匹配项 | 支持每个内容项内部混排富媒体 |
| 答案 | `answer` | 标准答案、参考答案、答案规则 | 以结构化答案为主，可扩展图片/文档答案 |
| 解析 | `analysis` | 答案解析、解题思路、考点、错因、视频讲解 | 支持多种解析方式并存，重点支持富媒体 |
| 材料 | `materials` | 阅读材料、听力材料、视频材料、案例材料 | 支持图片、视频、音频、文档、表格、代码 |
| 子题 | `children` | 材料题、听力题、案例题下的子题 | 每个子题拥有独立题干、内容、答案、解析 |

### 4.3 内联富媒体内容块

题干、选项、解析、材料都允许“中间插入”图片/视频/音频等内容，而不是只能挂在末尾。统一使用内容块数组表达顺序。

```json
{
  "blocks": [
    { "id": "b1", "type": "text", "text": "阅读下面材料，观察图片" },
    { "id": "b2", "type": "image", "fileId": 101, "caption": "材料图片" },
    { "id": "b3", "type": "text", "text": "然后回答下面问题。公式为：" },
    { "id": "b4", "type": "formula", "latex": "E = mc^2" },
    { "id": "b5", "type": "table", "data": [["年份", "数量"], ["2024", "100"]] },
    { "id": "b6", "type": "code", "language": "go", "code": "fmt.Println(\"hello\")" },
    { "id": "b7", "type": "video", "fileId": 102, "caption": "题目视频" },
    { "id": "b8", "type": "audio", "fileId": 103, "caption": "听力音频" },
    { "id": "b9", "type": "document", "fileId": 104, "caption": "参考文档" }
  ]
}
```

支持的内容块：

| block type | 说明 | 是否关联文件管理 |
|---|---|---|
| `text` | 普通文字/富文本 | 否 |
| `image` | 图片 | 是，`fileId -> sys_file_entries.id` |
| `video` | 视频 | 是，复用媒体预览/转码 |
| `audio` | 音频 | 是，复用媒体播放 |
| `document` | 文档 | 是，复用文档预览/下载 |
| `formula` | LaTeX/公式 | 否 |
| `table` | 表格数据 | 否 |
| `code` | 代码片段 | 否 |
| `quote` | 引用/材料摘录 | 否 |
| `divider` | 分隔线 | 否 |

### 4.4 解析设计：多种解析方式并存

解析不是一个纯文本字段，也不是只有一种解析。面向练习用户时，同一道题可以同时提供多种解析方式：

| 解析类型 | analysis type | 说明 | 示例 |
|---|---|---|---|
| 文字解析 | `text` | 基础文字讲解 | “本题考查 TCP 三次握手……” |
| 步骤解析 | `steps` | 分步骤讲解，适合数学、计算、推理 | 第一步、第二步、第三步 |
| 视频解析 | `video` | 老师讲解视频 | 5 分钟视频讲解 |
| 音频解析 | `audio` | 语音讲解 | 听力题、语言题讲解 |
| 图片解析 | `image` | 图解、标注图、思维导图 | 几何辅助线、流程图 |
| 文档解析 | `document` | PDF/Word 详细讲义 | 完整知识点文档 |
| 考点解析 | `knowledge` | 本题考查哪些知识点 | “JWT 生命周期、刷新机制” |
| 错因解析 | `mistake` | 常见错误、易错点 | “容易把 Refresh Token 放到 localStorage” |
| 方法解析 | `method` | 解题技巧、公式、套路 | “排除法”“代入法” |
| 关联题解析 | `related` | 推荐相似题/变式题 | 同知识点练习 |

推荐 `analysis` 结构：

```json
{
  "summary": {
    "blocks": [
      { "id": "a1", "type": "text", "text": "本题考查 JWT 双 Token 登录机制。" }
    ]
  },
  "sections": [
    {
      "type": "text",
      "title": "文字解析",
      "blocks": [
        { "id": "a2", "type": "text", "text": "Access Token 生命周期短，用于访问接口。" },
        { "id": "a3", "type": "image", "fileId": 201, "caption": "Token 刷新流程图" }
      ]
    },
    {
      "type": "steps",
      "title": "步骤解析",
      "steps": [
        { "title": "第一步", "blocks": [{ "type": "text", "text": "先判断 Access Token 是否过期。" }] },
        { "title": "第二步", "blocks": [{ "type": "text", "text": "再用 Refresh Token 换取新的 Access Token。" }] }
      ]
    },
    {
      "type": "video",
      "title": "视频讲解",
      "blocks": [
        { "id": "a4", "type": "video", "fileId": 202, "caption": "JWT 刷新流程视频解析" }
      ]
    },
    {
      "type": "mistake",
      "title": "易错点",
      "blocks": [
        { "id": "a5", "type": "text", "text": "不要把 Access Token 和 Refresh Token 的用途混淆。" }
      ]
    }
  ]
}
```

### 4.8 组合题结构：材料、阅读、听力、视频、文档

组合题使用父题 + 子题结构。父题保存材料，子题可以是任何题型，并拥有自己的解析。

```json
{
  "questionType": "listening",
  "stem": {
    "blocks": [{ "type": "text", "text": "听下面一段材料，回答问题。" }]
  },
```

## 5. 附件设计

### 5.1 附件类型

| 类型 | MIME/fileType | 使用场景 | 处理方式 |
|---|---|---|---|
| 图片 | `image/*` | 题干图、选项图、解析图、材料图 | 文件管理保存，前端通过预览 URL 渲染 |
| 文档 | `pdf/doc/docx/xls/xlsx` | 题目材料、解析附件、导入源文件 | 文件管理保存，支持预览/下载 |
| 音频 | `audio/*` | 听力材料、解析音频 | 写入媒体元数据，支持在线播放 |
| 视频 | `video/*` | 视频题材料、解析视频 | 写入媒体元数据，必要时转 HLS |
| 压缩包 | `zip/rar/7z` | 批量导入附件包 | 作为导入任务源文件，不直接展示为题目附件 |

### 5.2 附件使用位置

`usage` 必须明确文件在题目中的位置：

| usage | 说明 |
|---|---|
| `stem` | 题干附件 |
| `content` | 题目内容附件，例如选项图 |
| `option` | 具体选项附件 |
| `analysis` | 解析附件，图片/视频/音频/文档都可用 |
| `material` | 材料题、听力题、视频题、文档题材料 |
| `answer` | 答案附件，少量场景使用 |
| `import_source` | 导入源文件 |
| `export_result` | 导出结果文件 |

### 5.3 附件引用规则

1. 题库只保存 `sys_file_entries.id`，不保存 object key 和本地路径。
2. 题目引用附件时，必须检查文件未被删除。
3. 发布时把附件关系固化到题目版本中。
4. 删除题目不立即删除文件，只解除业务引用或标记关系失效。
5. 文件物理清理由文件管理模块的回收站、引用计数、定时任务统一处理。
6. 解析附件和题干附件同级管理，不能只给题干支持图片视频，解析必须同样支持。

## 6. 导入文件设计

### 6.1 导入入口

导入不直接把上传文件临时丢弃，而是走统一文件管理流程：

```text
上传文件 → 文件管理入库 → 创建题库导入任务 → 解析文件 → 生成题目草稿 → 人工检查 → 发布/提交审核
```

### 6.2 文件保存位置

建议系统自动维护以下文件夹：

```text
/题库/
├── 导入文件/
│   ├── Excel/
│   ├── Word/
│   ├── PDF/
│   └── 附件包/
├── 题目附件/
│   ├── 图片/
│   ├── 文档/
│   ├── 音频/
│   └── 视频/
└── 导出文件/
```

这些目录本质是 `sys_file_folders` 数据。题库导入任务引用文件管理中的 `fileId`，不直接维护上传路径。

### 6.3 导入任务状态

| 状态 | 说明 |
|---|---|
| `uploaded` | 文件已上传，等待解析 |
| `parsing` | 正在解析 Excel/Word/PDF/附件包 |
| `parsed` | 解析完成，生成待确认题目 |
| `partial_failed` | 部分题目解析失败 |
| `failed` | 文件整体解析失败 |
| `confirmed` | 用户确认导入结果，题目草稿已入库 |
| `published` | 导入生成的题目已发布或提交审核 |

### 6.4 导入附件处理

1. Excel/Word/PDF 中嵌入的图片、音频、视频，解析时抽取为文件并写入文件管理。
2. 附件包先作为源文件进入文件管理，解压后的每个附件也进入文件管理。
3. 解析出的题干、选项、解析、材料附件统一写入 `qb_question_attachments`。
4. 原始导入文件和附件包作为 `import_source` 关联到 `qb_question_import_tasks`，便于追溯。

## 7. 发布、解析与版本快照

### 7.1 为什么需要版本快照

题目被考试、练习、错题、解析统计引用后，不能因为管理员修改题目而改变历史记录。因此发布时生成版本快照：

```text
qb_questions 当前编辑态
    ↓ 发布
qb_question_versions 固化题干、内容、答案、解析、附件、可见范围
    ↓ 用户答题/考试/练习
后续答题记录引用 question_version_id
```

### 7.2 发布流程

```text
保存草稿
  ↓
结构校验：题型、题干、内容、选项、答案、解析、材料
  ↓
附件校验：文件存在、文件未删除、文件类型允许、媒体可播放或转码完成
  ↓
安全校验：HTML/XSS、文件类型、内容长度、JSON 深度
  ↓
权限校验：发布人是否有 public/group/private 发布权限
  ↓
生成 qb_question_versions
  ↓
固化 qb_question_attachments 到版本
  ↓
写入 qb_question_visibility_scopes
  ↓
状态变更为 published
```

### 7.3 查看解析流程

用户端请求解析时：

1. 校验题目版本是否 `published`。
2. 校验用户是否命中 `qb_question_visibility_scopes`。
3. 如果题目来自分组分享，校验用户是否在该分组或子分组。
4. 通过后返回题干、题目内容、答案、解析、附件预览 URL。
5. 未命中范围只返回无权限，不暴露答案和解析。

## 8. 分类、考点与来源体系设计

题库面向所有考试练习用户时，不能只靠一个简单分类树。推荐把“考试大类、具体考试、科目、章节分类、知识点、标签、来源”分层管理。

### 8.1 分类体系层级

```text
考试大类 qb_exam_categories
  ↓
具体考试 qb_exams
  ↓
科目/模块 qb_subjects
  ↓
章节/目录分类 qb_categories
  ↓
知识点/考点 qb_knowledge_points
  ↓
题目 qb_questions
```

例如：

```text
职业资格考试
└── 软考
    └── 系统架构设计师
        ├── 计算机组成与体系结构
        │   ├── CPU
        │   ├── 存储系统
        │   └── 总线
        └── 软件架构设计
            ├── 架构风格
            ├── 微服务
            └── 领域驱动设计
```

### 8.2 各层职责

| 层级 | 表 | 作用 | 关系 |
|---|---|---|---|
| 考试大类 | `qb_exam_categories` | 公考、软考、医考、法考、财会、学历、语言、职业技能等 | 可树形 |
| 具体考试 | `qb_exams` | 软考-系统架构师、大学英语四级、执业医师等 | 归属考试大类 |
| 科目/模块 | `qb_subjects` | 综合知识、案例分析、英语听力、申论、专业实务等 | 归属具体考试 |
| 章节分类 | `qb_categories` | 章节、目录、教材结构、课程结构 | 归属考试/科目，可树形 |
| 知识点/考点 | `qb_knowledge_points` | 细粒度考点，可多层级 | 可挂分类，题目可多选 |
| 标签 | `qb_question_tags` + `sys_tag` | 高频、易错、真题、模拟题、重点、收藏等 | 题目多对多 |
| 来源 | `qb_question_sources` | 真题、模拟、章节练习、导入、自建、AI 生成等 | 题目可关联来源 |

### 8.3 题目归类规则

| 维度 | 规则 |
|---|---|
| 考试 | 一道题可指定一个主要考试 `exam_id`，通用题可为空或归到通用考试库 |
| 科目 | 一道题可指定一个主要科目 `subject_id` |
| 章节分类 | 一道题有一个主分类 `category_id`，用于目录树筛选 |
| 知识点 | 一道题可以关联多个知识点，通过 `qb_question_knowledge_points` 实现多对多 |
| 标签 | 一道题可以关联多个标签，复用系统标签能力或通过题库标签关系表绑定 |
| 来源 | 一道题可以关联一个来源，记录真题年份、地区、考试批次、导入任务等 |

推荐列表筛选顺序：

```text
考试大类 → 具体考试 → 科目 → 章节分类 → 知识点 → 题型 → 难度 → 来源 → 标签
```

### 8.4 分类和知识点的区别

| 维度 | 分类/章节 `qb_categories` | 知识点/考点 `qb_knowledge_points` | 标签 `sys_tag`/`qb_question_tags` |
|---|---|---|---|
| 用途 | 组织题库目录，适合树形浏览 | 标识题目考查内容，适合练习推荐和统计 | 自由标记，适合运营和筛选 |
| 数量关系 | 一题一个主分类 | 一题多个知识点 | 一题多个标签 |
| 是否树形 | 是 | 是，可选 | 通常扁平 |
| 示例 | 软考 → 软件架构设计 → 架构风格 | 微服务、DDD、缓存一致性 | 高频、易错、真题、模拟题 |

### 8.5 题目来源设计

题目来源用于区分题从哪里来，方便考试练习、真题训练和版权追溯。

| source_type | 说明 |
|---|---|
| `real_exam` | 历年真题 |
| `mock_exam` | 模拟题 |
| `chapter_practice` | 章节练习题 |
| `daily_practice` | 每日练习题 |
| `manual` | 人工录入 |
| `import` | 文件导入 |
| `ai_generated` | AI 生成题 |
| `user_created` | 用户自建题 |

来源可以记录：年份、地区、考试名称、卷别、题号、导入任务、版权说明。

## 12. 典型流程

### 12.1 管理员导入题目并发布到公共题库

```text
管理员上传 Excel/Word/PDF → 文件管理保存 fileId
  ↓
创建 qb_question_import_tasks(file_id)
  ↓
解析文件并抽取图片/音频/视频/文档到文件管理
  ↓
生成 qb_question_import_items
  ↓
管理员确认导入结果
  ↓
生成 qb_questions 草稿
  ↓
批量发布
  ↓
生成 qb_question_versions + public 可见范围
```

### 12.2 教师创建题目并分享给班级/分组

```text
教师创建私有题目
  ↓
上传题干图片、题目视频、解析音频、解析文档到文件管理
  ↓
关联附件到题干/content/analysis/materials
  ↓
发布题目
  ↓
选择分组：高三一班 / 软考冲刺班
  ↓
写入 qb_question_visibility_scopes(scope_type=group, scope_id=分组ID)
  ↓
该分组用户可查看题目和解析
```

### 12.3 用户查看带视频解析的题目

```text
用户请求 /api/v1/study/questions/:id/analysis
  ↓
校验 token
  ↓
校验题目 published
  ↓
校验用户命中 public/group/user/role 范围
  ↓
读取 qb_question_versions.analysis
  ↓
把 analysis 中的 video/audio/image/document fileId 转为预览/播放地址
  ↓
返回富媒体解析内容
```

### 12.4 已发布题目再次修改

```text
编辑已发布题目
  ↓
保存为草稿编辑态，不影响 current_version
  ↓
再次发布
  ↓
生成 version_no + 1
  ↓
新练习/新考试使用新版本，历史记录继续使用旧版本
```

## 13. 后台二级菜单规划

结合当前系统菜单风格，题库管理建议作为一级菜单“题库管理”，下设 **8 个二级菜单**。第一版直接全部落地 8 个二级菜单，不再拆分后续菜单。

### 13.1 推荐二级菜单

| 菜单 | 路由 | 组件建议 | 权限码 | 是否首版 | 职责 |
|---|---|---|---|---|---|
| 题目管理 | `/question/list` | `/question/list/index` | `question:view` | 是 | 题目列表、筛选、新增、编辑、发布、下架、删除 |
| 题目导入 | `/question/import` | `/question/import/index` | `question:import` | 是 | 上传导入源文件、解析任务、错误报告、确认入库、批量发布 |
| 分类科目 | `/question/category` | `/question/category/index` | `question:category` | 是 | 考试大类、具体考试、科目、章节分类树维护 |
| 知识考点 | `/question/knowledge` | `/question/knowledge/index` | `question:knowledge` | 是 | 知识点/考点树、重要程度、题目关联统计 |
| 审核发布 | `/question/audit` | `/question/audit/index` | `question:audit` | 是 | 公共题目审核、驳回、批量审核、发布记录 |
| 题目分享 | `/question/share` | `/question/share/index` | `question:share:view` | 是 | 分组/用户/链接分享，分享有效期和访问统计 |
| 来源标签 | `/question/source` | `/question/source/index` | `question:source:view` | 是 | 真题来源、模拟题来源、年份地区、标签维护 |
| 题库统计 | `/question/statistics` | `/question/statistics/index` | `question:statistics:view` | 是 | 题量、题型、难度、知识点、正确率、使用次数统计 |

### 13.2 为什么建议 8 个二级菜单

| 菜单能力 | 是否应该独立 | 原因 |
|---|---|---|
| 题目管理 | 是 | 高频核心操作，不能和导入、分类混在一起 |
| 题目导入 | 是 | 导入有任务状态、解析报告、错误处理，流程独立 |
| 分类科目 | 是 | 考试/科目/章节是题库基础数据，维护频率和题目不同 |
| 知识考点 | 是 | 知识点用于练习推荐和统计，一题多知识点，和章节分类不同 |
| 审核发布 | 是 | 内容审核是独立工作台，适合内容管理员集中处理 |
| 题目分享 | 是 | 分组授权、链接分享、访问统计会越来越复杂，第一版直接独立 |
| 来源标签 | 是 | 真题年份、地区、来源、标签适合运营维护，第一版直接独立 |
| 题库统计 | 是 | 数据分析页面，不应塞进题目列表，第一版直接独立 |

### 13.3 首版落地建议

首版直接上线 8 个二级菜单：

```text
题库管理
├── 题目管理
├── 题目导入
├── 分类科目
├── 知识考点
├── 审核发布
├── 题目分享
├── 来源标签
└── 题库统计
```

虽然 8 个菜单首版全部落地，但实现时仍可按主流程优先级推进：先保证题目、导入、分类、知识点、审核可用，再完善分享、来源标签和统计页面的数据深度。

### 13.4 菜单按钮权限建议

| 二级菜单 | 按钮权限 |
|---|---|
| 题目管理 | `question:create`、`question:edit`、`question:delete`、`question:publish`、`question:archive` |
| 题目导入 | `question:import`、`question:import:parse`、`question:import:confirm`、`question:import:publish` |
| 分类科目 | `question:category:add`、`question:category:edit`、`question:category:delete`、`question:exam:manage`、`question:subject:manage` |
| 知识考点 | `question:knowledge:add`、`question:knowledge:edit`、`question:knowledge:delete`、`question:knowledge:bind` |
| 审核发布 | `question:audit:view`、`question:audit:approve`、`question:audit:reject` |
| 题目分享 | `question:share:create`、`question:share:disable`、`question:share:delete` |
| 来源标签 | `question:source:manage`、`question:tag:manage` |
| 题库统计 | `question:statistics:view` |

## 15. 实施优先级

### P0：先落地核心闭环

1. 新建 `qb_questions`、`qb_question_versions`、`qb_question_attachments`、`qb_question_visibility_scopes`。
2. 题目 CRUD、题型结构、题干富媒体、解析富媒体、附件关联。
3. 发布生成版本快照。
4. 用户端按可见范围查询已发布题目和解析。
5. 复用文件管理上传、预览、播放、下载能力。

### P1：导入与分组分享

1. 新建 `qb_question_import_tasks`、`qb_question_import_items`。
2. Excel 基础导入，保留源文件，生成失败报告。
3. 发布到分组，分组成员可见。
4. 后台题目列表按题型、分组、状态筛选。

### P2：高级题型与高级附件

1. Word/PDF 导入。
2. 图片抽取、附件包解析。
3. 听力题、视频题、文档材料题。
4. 音视频元数据检查、转码状态联动。

### P3：审核、分享链接、统计

1. 公共题目审核队列。
2. 题目链接分享。
3. 题目使用统计、正确率、收藏数。
4. 错题本、考试快照、学习分析接入。

## 16. 当前文档中的待实现说明

本设计是结合当前系统能力后的题库模块方案，其中：

- 文件管理、分组管理、角色权限、文件分享、媒体元数据等基础模块在当前系统已有雏形。
- 题库业务表统一使用 `qb_` 前缀，避免和系统 `sys_` 表混用。
- `qb_questions`、`qb_question_versions`、`qb_question_attachments`、`qb_question_visibility_scopes`、`qb_question_import_tasks` 等题库业务表尚需新增。
- “班级”暂不单独建模，先使用 `sys_groups` 分组承载；后续如有班级模块，再通过班级与分组映射扩展。
- 上传、预览、下载、转码不在题库模块重复实现，统一调用 `/api/v1/files/*` 相关能力。
- 题目查重、组合题父子结构、操作日志、编辑态/发布态边界、答案解析可见策略、回收站恢复、来源关系、唯一约束、安全校验等关键修正见 [设计补充与修正](设计补充与修正.md)。
