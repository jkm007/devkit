## 一、错题本系统

### 1.1 数据模型

```sql
-- 错题记录表
CREATE TABLE wrong_books (
    id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id     BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    question_id BIGINT UNSIGNED NOT NULL COMMENT '题目ID',
    category_id BIGINT UNSIGNED DEFAULT 0 COMMENT '所属分类ID',
    wrong_count INT UNSIGNED DEFAULT 1 COMMENT '错误次数',
    last_wrong_at DATETIME COMMENT '最后一次错误时间',
    is_mastered TINYINT DEFAULT 0 COMMENT '是否已掌握 0=未掌握 1=已掌握',
    mastered_at DATETIME COMMENT '掌握时间',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_question (user_id, question_id),
    KEY idx_user_mastered (user_id, is_mastered),
    KEY idx_user_category (user_id, category_id)
) COMMENT = '错题本';
```

### 1.2 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/study/wrong` | GET | 错题列表（分页+筛选） |
| `/api/v1/study/wrong/:questionId` | POST | 添加错题（练习提交时自动调用） |
| `/api/v1/study/wrong/:questionId` | DELETE | 移除错题 |
| `/api/v1/study/wrong/:questionId/mastered` | PUT | 标记已掌握 |
| `/api/v1/study/wrong/batch-mastered` | POST | 批量标记已掌握 |
| `/api/v1/study/wrong/stats` | GET | 错题统计（分类分布/正确率趋势） |
| `/api/v1/study/wrong/export` | GET | 导出错题（下载 PDF/Excel） |

### 1.4 错题收集逻辑

```
练习提交 → 后端比对答案 → 错误题目自动写入 wrong_books
  → wrong_count++（重复错误累加）
  → last_wrong_at = NOW()
  → 如果连续 3 次正确 → is_mastered = 1
```

### 1.5 艾宾浩斯复习计划

| 复习轮次 | 间隔时间 | 说明 |
|----------|----------|------|
| 第 1 轮 | 1 天后 | 首次复习 |
| 第 2 轮 | 2 天后 | 二次复习 |
| 第 3 轮 | 4 天后 | 三次复习 |
| 第 4 轮 | 7 天后 | 四次复习 |
| 第 5 轮 | 15 天后 | 五次复习 → 掌握 |

每次复习正确 → 进入下一轮  
复习错误 → 重置到第 1 轮

## 二、智能练习

### 2.1 算法逻辑

```
智能练习 = 薄弱知识点推荐 + 艾宾浩斯复习 + 难度自适应
```

**推荐权重**：
```
score = 错误次数 × 0.3
      + 距上次练习天数 × 0.2
      + 知识点掌握度(低) × 0.3
      + 用户设定的优先级 × 0.2
```

**难度自适应**：
- 连续 3 题正确 → 难度 +1
- 连续 2 题错误 → 难度 -1
- 默认从用户设定难度开始

### 2.2 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/study/practice/smart` | POST | 智能练习（返回推荐题目） |
| `/api/v1/study/practice/analysis` | GET | 练习分析（薄弱知识点/趋势） |

### 2.3 请求参数

```typescript
interface SmartPracticeRequest {
  count?: number;           // 题目数量，默认 20
  categories?: number[];    // 限定分类
  focusKnowledge?: string[]; // 聚焦知识点
  difficulty?: number;      // 初始难度 1-3
  mode?: 'review' | 'weak' | 'mixed'; // 复习模式/薄弱模式/混合模式
}
```

## 三、分类绑定

### 3.1 数据模型

```sql
-- 用户分类绑定表
CREATE TABLE user_category_bindings (
    id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id     BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    category_id BIGINT UNSIGNED NOT NULL COMMENT '分类ID',
    is_primary  TINYINT DEFAULT 0 COMMENT '是否主分类 0=副 1=主',
    bound_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_category (user_id, category_id),
    KEY idx_user (user_id)
) COMMENT = '用户分类绑定';
```

**规则**：
- 每个用户最多绑定 **3 个分类**
- 其中 1 个为主分类（标记 is_primary = 1）
- 绑定后首页/题库/练习默认筛选该分类

### 3.2 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/user/category-bindings` | GET | 获取用户绑定的分类 |
| `/api/v1/user/category-bindings` | POST | 绑定分类（最多 3 个） |
| `/api/v1/user/category-bindings/:id` | PUT | 更新绑定（设为主分类） |
| `/api/v1/user/category-bindings/:id` | DELETE | 解绑分类 |

### 3.3 请求参数

```typescript
interface BindCategoryRequest {
  categoryId: number;
  isPrimary?: boolean;  // 是否设为主分类
}
```

### 3.4 页面设计

**页面路由**：`pages/profile/categories.vue`

```
我的分类
├── 当前绑定（最多 3 个）
│   ├── 主分类（带"主"标签，蓝色高亮）
│   ├── 副分类 1
│   └── 副分类 2（可能为空）
├── 操作
│   ├── 添加分类（从分类树选择）
│   └── 解绑（点击分类旁的 ✕）
├── 提示
│   └── "绑定分类后，首页和题库将默认显示该分类内容"
└── 分类选择弹窗
    └── 分类树（单选）
```

### 3.5 绑定流程

```
点击"添加分类" → 弹出分类树 → 选择分类 → 确认
  → 检查是否已满 3 个
    → 是：提示"请先解绑一个分类"
    → 否：写入绑定表 → 刷新页面
```
