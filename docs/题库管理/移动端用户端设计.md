# 移动端用户端设计

## 1. 概述

移动端是用户端（学习/练习/查看）的入口，面向普通用户，提供题库浏览、题目查看与练习、收藏、笔记、消息通知等功能。

- **项目名称**：DevKit 移动端用户端
- **技术栈**：uni-app 3.x + Vue 3 + TypeScript + uView Plus
- **目标平台**：H5（移动端浏览器）、微信小程序、App（iOS / Android）
- **后端依赖**：DevKit backend-server（Go + Gin + GORM + MySQL + Redis）
- **接口前缀**：管理端 `/api/v1`，认证端 `/auth`（无前缀），公开端 `/api/v1/public`
- **认证方式**：JWT Access Token + Refresh Token 静默刷新

### 2.4 练习页面（pages/practice/index + session + result）

| 功能点 | 功能描述 |
|-------|---------|
| 练习入口 | 选择分类/知识点/题型/难度开始练习 |
| 练习答题 | 逐题展示，支持单选/多选/判断/填空等题型作答 |
| 即时反馈 | 提交答案后立即显示正确/错误、答案和解析 |
| 练习结果 | 练习完成后显示正确率、用时、错题列表 |

**答题答案本地缓存**：
- 答题过程中答案同步写入 `uni.setStorageSync`
- 网络恢复后自动同步到后端
- 防止网络中断丢失答题进度

## 3. API 接口规范

### 3.1 统一响应格式

**成功响应**：
```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

**分页响应**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 1234,
    "page": 1,
    "pageSize": 20,
    "totalPages": 62
  }
}
```

**错误响应**：
```json
{
  "code": 40003,
  "message": "题目不存在",
  "details": { "question_id": 123 }
}
```

**错误码表**：

| code | 说明 |
|------|------|
| 40001 | 参数校验失败 |
| 40003 | 资源不存在 |
| 40004 | 资源已被删除 |
| 40005 | 没有操作权限 |
| 40006 | 资源状态不允许此操作 |
| 40007 | 文件已被删除 |
| 40012 | 分享链接已过期或已禁用 |
| 403001 | 需要验证码 |
| 401 | Token 无效或过期 |
| 403 | 权限不足 |
| 429 | 请求过于频繁 |

**请求头规范**：

| Header | 说明 | 示例 |
|--------|------|------|
| Authorization | Bearer Token | `Bearer eyJhbGci...` |
| X-Device-ID | 设备唯一标识 | `device_uuid` |
| X-Client-Type | 客户端类型 | `h5` / `app` / `miniapp` |
| X-Platform | 平台 | `ios` / `android` |
| X-App-Version | App 版本 | `1.0.0` |
| X-System-Version | 系统版本 | `17.0` |
| X-Device-Model | 设备型号 | `iPhone14,2` |
| X-Channel | 渠道 | `appstore` / `wechat` |

## 4. Token 刷新机制

移动端 `request.ts` 必须实现 Refresh Token 静默刷新：

1. 请求返回 401 时，检查是否有 Refresh Token
2. 有 Refresh Token → 调用 `/auth/refresh` 静默刷新
3. 刷新成功 → 用新 Token 重试原请求
4. 刷新失败 → 清除 Token，跳转登录页
5. **并发请求处理**：确保同一时间只有一个刷新请求在进行，其他请求等待刷新结果

**实现要点**：
- 使用队列机制：多个 401 请求进入等待队列
- 第一个触发刷新，后续请求等待刷新结果
- 刷新成功 → 队列中所有请求用新 Token 重试
- 刷新失败 → 队列中所有请求返回 401，跳转登录

## 5. WebSocket 实时通知

移动端需对接后端 WebSocket Hub 实现实时通知推送。

### 5.1 连接配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 连接地址 | `ws://host/api/v1/ws?token=xxx` | token 通过 query 参数传递 |
| 安全协议 | `wss://` | 生产环境必须使用 |
| 心跳间隔 | 30 秒 | 发送 ping，服务端回复 pong |
| 断线重连 | 指数退避 | 1s → 2s → 4s → 8s → 最大 30s |
| 最大重试次数 | 5 次 | 超过后提示用户手动刷新 |

### 5.2 通知类型

| 类型 | 说明 | 处理方式 |
|------|------|---------|
| `notification` | 站内通知更新 | 刷新通知列表 + 更新未读数量角标 |
| `login_alert` | 新设备登录提醒 | 弹出安全警告 |
| `announcement` | 系统公告 | 写入通知列表 |
| `role_approved` | 角色申请通过 | 写入通知列表 |
| `role_rejected` | 角色申请驳回 | 写入通知列表 |

### 5.3 消息展示

- **App 前台运行**：角标 + 站内消息列表更新
- **App 后台运行**：通知栏推送（App / 小程序订阅消息）
- **H5**：页面内通知提示

## 6. 响应格式与错误处理

### 6.1 统一响应格式

所有接口使用统一响应结构：

```typescript
interface ApiResponse<T = any> {
  code: number;
  message: string;
  data: T;
}

interface PageResponse<T = any> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
  totalPages: number;
}
```

### 6.2 错误处理

```typescript
// 错误码分类
const ErrorCode = {
  VALIDATION_ERROR: 40001,     // 参数校验失败
  NOT_FOUND: 40003,            // 资源不存在
  DELETED: 40004,              // 资源已被删除
  NO_PERMISSION: 40005,        // 没有操作权限
  STATE_ERROR: 40006,          // 资源状态不允许
  FILE_DELETED: 40007,         // 文件已被删除
  SHARE_EXPIRED: 40012,        // 分享链接已过期
  CAPTCHA_REQUIRED: 403001,    // 需要验证码
} as const;
```

**全局错误处理**：
- `40001` → Toast 提示具体校验信息
- `40003` / `40004` → Toast 提示"资源不存在"
- `40005` → Toast 提示"没有权限"
- `401` → 触发 Token 刷新或跳转登录
- `403` → Toast 提示"权限不足"
- `429` → Toast 提示"操作过于频繁，请稍后重试"

## 10. 性能优化方案

| 优化项 | 方案 |

| 分包加载 | 按模块分包（首页+登录为核心包，题库/练习/个人中心为分包），首屏只加载核心包 |

### 11.1 文件上传-预览流程（移动端）

```text
编辑器中点击"插入图片"
  ↓
调用 uni.chooseImage / uni.chooseMessageFile
  ↓
分片上传（大文件）或直传（小文件）：
  1. 秒传检查 → POST /api/v1/files/upload/check
  2. 初始化上传 → POST /api/v1/files/upload/init
  3. 上传分片 → POST /api/v1/files/upload/part
  4. 合并分片 → POST /api/v1/files/upload/complete
  ↓
获取 fileId + 预览URL
  ↓
编辑器中渲染 ImageBlock(fileId)
```

视频上传后轮询 `/api/v1/files/:id/media-status` 等待转码完成，播放器使用 HLS 流。

## 12. 安全设计

### 12.1 Token 安全

- Access Token 有效期 7 天，Refresh Token 有效期 30 天
- Token 存储在 `uni.setStorageSync`，不暴露给 WebView
- 401 自动刷新，刷新失败清除 Token 跳转登录
- 登录态变更通知：服务端踢人后推送 WebSocket 通知

### 12.2 接口安全

- 所有接口 HTTPS（生产环境）
- Token 注入请求头：`Authorization: Bearer xxx`
- CSRF 防护：对敏感操作添加 CSRF Token
- 防暴力枚举：登录接口限制频率 + 验证码

### 12.3 分享安全

- 分享码使用 `crypto/rand` 生成 24 字节 → base64url 编码 32 字符
- 无法暴力枚举，有效期可设置
- 支持最大访问次数限制
- 分享访问记录写入审计日志（IP、user-agent、时间）
