## 1. 数据库规范补充

### 1.1 时间字段 DEFAULT 定义

**问题**：所有 `created_at`、`updated_at` 缺少 `DEFAULT CURRENT_TIMESTAMP(3)`。

**修复**：

```sql
-- 统一时间字段定义规范
created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
deleted_at DATETIME(3) NULL COMMENT '软删除时间',

-- 业务时间字段
published_at DATETIME(3) NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '发布时间',
reviewed_at DATETIME(3) NULL COMMENT '审核时间',
confirmed_at DATETIME(3) NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '确认时间',
accessed_at DATETIME(3) NULL COMMENT '最后访问时间',
```

### 1.4 外键约束策略

**决策**：与现有系统保持一致，**不使用数据库级 FOREIGN KEY 约束**，由应用层控制引用完整性和删除保护。

原因：
- 现有系统 `sys_user_roles`、`sys_group_roles` 等均无外键约束
- 软删除场景下外键约束会导致级联删除困难
- 跨模块引用（`qb_questions.created_by -> sys_users.id`）不适合数据库级外键
- 应用层已有删除保护逻辑（检查引用数）

### 2.3 幂等性设计

**重复发布防护**：

```go
func PublishQuestion(questionID uint64, userID uint64) error {
    // 1. SELECT FOR UPDATE 锁定题目行
    tx := db.Begin()
    var q Question
    tx.Set("gorm:query_option", "FOR UPDATE").First(&q, questionID)

    // 2. 校验状态
    if q.Status == "published" {
        // 检查是否是并发重复点击：短时间内已有新版本
        var recentCount int64
        tx.Model(&QuestionVersion{}).Where("question_id = ? AND created_at > ?", questionID, time.Now().Add(-30*time.Second)).Count(&recentCount)
        if recentCount > 0 {
            tx.Rollback()
            return ErrConcurrentPublish
        }
    }

    // 3. 执行发布逻辑...
    tx.Commit()
}
```

**重复提交审核防护**：

```go
func SubmitAudit(questionID uint64) error {
    q := GetQuestion(questionID)
    if q.Status == "pending" {
        // 幂等返回，不报错
        return nil
    }
    if q.Status != "draft" && q.Status != "rejected" {
        return ErrCannotSubmitAudit
    }
    // ...
}
```

**批量操作重试幂等**：

批量接口返回 `{success: [], failed: []}`，重试时自动跳过已成功的项目。

```go
// gin 中间件：校验 :id 为正整数
func ValidateUint64Param() gin.HandlerFunc {
    return func(c *gin.Context) {
```

## 3. 业务流程补充

### 3.1 分类/知识点删除后的题目处理

| 场景 | 处理策略 |
|---|---|
| 分类软删除 | 题目 `category_id` 保持不变用于追溯，前端展示"已删除的分类" |
| 分类合并 | 自动迁移所有题目的 `category_id` 到新分类 |
| 知识点合并 | 迁移 `qb_question_knowledge_points` 引用，冲突的记录跳过 |
| 知识点删除 | 删除保护：有关联题目时不能直接删除，需先解除绑定或合并 |
| 考试删除 | 删除保护：有关联科目/题目/来源时不能删除 |
| 科目删除 | 删除保护：有关联分类/知识点/题目时不能删除 |

知识点合并接口：

```
POST /api/v1/question-knowledge/:id/merge
Body: { "target_knowledge_id": 123 }

执行：
1. 将所有引用 source_id 的 qb_question_knowledge_points 改为 target_id
2. 唯一约束冲突的记录跳过
3. 删除 source_id 的绑定记录
4. 软删除 source_id
5. 记录操作日志
```

### 3.2 用户被删除后题目处理

1. 用户模块使用软删除，`sys_users.deleted_at` 标记但保留记录。
2. 题目列表展示时，如果创建人已删除，显示"已删除用户"。
3. 提供"转移题目"功能：

```
POST /api/v1/questions/batch-transfer
Body: { "question_ids": [1,2,3], "target_user_id": 5 }
```

4. 公共题库题目（`resource_type=public`）不受用户删除影响。

### 3.3 分组被删除后可见性处理

1. 分组模块使用软删除。
2. 分组删除时，检查可见范围引用：

```
GET /api/v1/system/group/:id/used-by
Response: { "question_visibility_count": 15, "question_share_count": 3 }
```

3. 提供选项：
   - a) 解除可见范围关联（删除相关 `qb_question_visibility_scopes` 记录）
   - b) 迁移到另一个分组
   - c) 确认删除并级联解除

4. `qb_question_shares` 中 `share_type=group` 的记录自动标记为过期。

### 3.6 回收站过期清理

定时任务设计：

```go
// 每天凌晨 2 点执行
func CleanupExpiredRecycleQuestions() {
    // 1. 查询过期题目
    var expired []Question
    db.Where("deleted_at IS NOT NULL AND recycle_expire_at IS NOT NULL AND recycle_expire_at < NOW()").Find(&expired)

    for _, q := range expired {
        // 2. 发送通知给创建人
        s.notifService.Create(&model.Notification{
            UserID: q.CreatedBy,
            Type:   "question_permanently_deleted",
            Title:  "题目已永久删除",
            Content: fmt.Sprintf("题目「%s」已从回收站永久删除", q.Title),
        })

        // 3. 永久删除题目（物理删除或标记 permanent_deleted）
        // 4. 删除草稿附件（question_version_id=0）
        // 5. 保留版本快照、答题记录、分享记录
    }
}
```

回收站过期时间默认 30 天：

```sql
-- 软删除时设置
UPDATE qb_questions SET deleted_at = NOW(), recycle_expire_at = DATE_ADD(NOW(), INTERVAL 30 DAY) WHERE id = ?
```

## 5. 运维和监控

### 5.1 导入任务超时处理

```go
const (
    MaxParseTime       = 30 * time.Minute
    ParseTimeoutCheck  = 5 * time.Minute
)

// 定时任务：标记超时的导入任务
func MarkTimeoutImportTasks() {
    result := db.Model(&ImportTask{}).
        Where("status = 'parsing' AND created_at < ?", time.Now().Add(-MaxParseTime)).
        Updates(map[string]interface{}{
            "status":       "failed",
            "error_report": `{"error":"解析超时，请重试","code":"timeout"}`,
            "updated_at":   time.Now(),
        })
    if result.RowsAffected > 0 {
        log.Printf("marked %d import tasks as timeout", result.RowsAffected)
    }
}
```

### 5.2 版本表数据量管理

| 策略 | 说明 |
|---|---|
| 保留策略 | 保留最近 5 个版本 + 当前活跃版本 |
| 归档 | 历史版本迁移到 `qb_question_versions_archive` |
| 监控 | 每题平均版本数、版本表总行数、存储大小 |
| 压缩 | 相邻版本差异极小时可选跳过生成新版本 |

### 5.3 存储空间预估

```
每题基础数据：~32KB（stem 10K + content 5K + answer 2K + analysis 10K + materials 5K）
每题版本快照：~32KB × 平均 3 版本 = ~96KB
每题附件记录：~1.5KB
每题操作日志：~10KB

10 万题 ≈ 14 GB（数据库）
10 万题 × 平均 5MB 附件 ≈ 500 GB（文件存储）

告警阈值：
- 数据库：50GB 警告 / 100GB 严重
- 文件存储：200GB 警告 / 500GB 严重
```

## 6. 模块交互补充

### 6.1 qb_question_logs 与系统日志的关系

| 日志类型 | 表 | 职责 | 复用建议 |
|---|---|---|---|
| 安全日志 | `sys_security_logs` | 登录失败、越权尝试、密码相关 | 不复用 |
| 操作日志 | `qb_question_logs` | 题库业务操作 | 第一版独立，后续可迁移为统一操作日志的 module_type |
| 导入/分享业务详情 | `qb_question_import_tasks` / `qb_question_shares` | 详细业务数据 | 独立 |

`qb_question_logs` 与 `sys_security_logs` 保持字段一致性（`operator_id`、`ip`、`user_agent`、`created_at`），便于后续统一查询。

### 6.2 题目分享与文件分享对齐

| 维度 | 统一标准 |
|---|---|
| 分享码生成 | `crypto/rand` 24 字节 → base64url 32 字符 |
| 有效期 | `expire_at` 可选，默认 7 天 |
| 访问次数 | `max_access` + `access_count` |
| 访问审计 | 独立日志表（`qb_question_share_access_logs` / 文件分享参考设计） |
| 状态 | 1 有效 / 2 过期 / 3 禁用 |

### 6.3 sys_group_members 表

```sql
CREATE TABLE sys_group_members (
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  group_id BIGINT UNSIGNED NOT NULL COMMENT 'sys_groups.id',
  user_id BIGINT UNSIGNED NOT NULL COMMENT 'sys_users.id',
  role_in_group VARCHAR(20) DEFAULT 'member' COMMENT 'admin/member',
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_sys_group_member (group_id, user_id),
  INDEX idx_sys_group_member_user (user_id),
  INDEX idx_sys_group_member_group (group_id)

```
