# 题库管理设计补充与修正

本文补充题库第一版开发前必须明确的关键设计，覆盖题目查重、组合题父子结构、操作日志、编辑态/发布态、答案解析可见策略、唯一约束、权限码细化和接口总览修正。

---

## 1. 题目查重与内容指纹

### 1.1 设计目标

题库支持导入和人工录入，如果没有查重，会出现大量重复题、相似题、真题重复导入问题。第一版必须支持基础查重。

### 1.2 查重字段

在 `qb_questions` 增加：

```sql
ALTER TABLE qb_questions
  ADD COLUMN stem_hash VARCHAR(64) DEFAULT '' COMMENT '题干内容指纹',
  ADD COLUMN content_hash VARCHAR(64) DEFAULT '' COMMENT '题干+内容+答案综合指纹',
  ADD COLUMN answer_hash VARCHAR(64) DEFAULT '' COMMENT '答案指纹';
```

### 1.3 指纹生成规则

| 指纹 | 生成内容 | 用途 |
|---|---|---|
| `stem_hash` | 题干文本去空格、去 HTML、附件 block 只保留 file hash | 识别相似题干 |
| `content_hash` | 题干 + 选项/填空/子题结构 + 答案 | 判断是否完全重复 |
| `answer_hash` | 标准答案 JSON 规范化后 hash | 辅助判断答案变化 |

### 1.4 查重流程

```text
新增/导入题目
  ↓
规范化题干、内容、答案
  ↓
生成 stem_hash/content_hash/answer_hash
  ↓
查询 qb_questions 中相同 content_hash
  ↓
如果存在：提示重复题，可跳过/覆盖/继续创建
  ↓
如果 stem_hash 相同但 content_hash 不同：提示相似题
```

### 1.5 推荐新增表 `qb_question_duplicates`

```sql
CREATE TABLE qb_question_duplicates (
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  question_id BIGINT UNSIGNED NOT NULL COMMENT '当前题目 qb_questions.id',
  duplicate_question_id BIGINT UNSIGNED NOT NULL COMMENT '疑似重复题 qb_questions.id',
  duplicate_type VARCHAR(20) NOT NULL COMMENT 'same_content/similar_stem/same_source',
  similarity DECIMAL(5,2) DEFAULT 100.00 COMMENT '相似度',
  status VARCHAR(20) DEFAULT 'pending' COMMENT 'pending/ignored/merged/confirmed',
  created_by BIGINT UNSIGNED DEFAULT 0 COMMENT 'sys_users.id',
  created_at DATETIME(3) NULL,
  updated_at DATETIME(3) NULL,
  UNIQUE KEY uk_qb_duplicate_pair (question_id, duplicate_question_id),
  INDEX idx_qb_duplicates_question_id (question_id),
  INDEX idx_qb_duplicates_status (status)
);
```

### 1.6 接口与权限

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| POST | `/api/v1/questions/check-duplicate` | `question:view` | 新增/导入前查重 |
| GET | `/api/v1/questions/:id/duplicates` | `question:view` | 查看疑似重复题 |
| POST | `/api/v1/questions/duplicates/:id/ignore` | `question:edit` | 忽略重复提示 |
| POST | `/api/v1/questions/duplicates/:id/confirm` | `question:edit` | 确认为重复 |
| POST | `/api/v1/questions/duplicates/:id/merge` | `question:edit` | 合并重复题 |

## 2. 组合题父子结构

### 2.1 问题说明

材料题、阅读理解、听力题、视频题、案例分析题不能只把子题放在 JSON 里，否则无法单独统计子题正确率、收藏、错题、难度和知识点。

### 2.2 `qb_questions` 补充字段

```sql
ALTER TABLE qb_questions
  ADD COLUMN parent_id BIGINT UNSIGNED DEFAULT 0 COMMENT '父题ID，组合题子题使用',
  ADD COLUMN is_group TINYINT DEFAULT 0 COMMENT '是否组合题父题',
  ADD COLUMN sub_index INT DEFAULT 0 COMMENT '子题排序',
  ADD INDEX idx_qb_questions_parent_id (parent_id),
  ADD INDEX idx_qb_questions_group (is_group, parent_id, sub_index);
```

### 2.3 规则

| 场景 | 规则 |
|---|---|
| 普通题 | `parent_id=0`，`is_group=0` |
| 组合题父题 | `parent_id=0`，`is_group=1`，保存公共材料和说明 |
| 组合题子题 | `parent_id=父题ID`，`is_group=0`，保存自己的题干、内容、答案、解析 |
| 发布 | 父题和子题一起生成版本，子题版本记录父版本关系 |
| 统计 | 子题可单独统计，父题可汇总子题统计 |

### 2.4 版本表补充字段

```sql
ALTER TABLE qb_question_versions
  ADD COLUMN parent_version_id BIGINT UNSIGNED DEFAULT 0 COMMENT '组合题父版本ID',
  ADD COLUMN sub_index INT DEFAULT 0 COMMENT '子题排序',
  ADD INDEX idx_qb_question_versions_parent (parent_version_id, sub_index);
```

### 2.5 接口补充

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| POST | `/api/v1/questions/:id/children` | `question:create` | 给组合题新增子题 |
| GET | `/api/v1/questions/:id/children` | `question:view` | 查看子题列表 |
| PUT | `/api/v1/questions/:id/children/sort` | `question:edit` | 子题排序 |
| DELETE | `/api/v1/questions/:id/children/:childId` | `question:delete` | 删除子题 |

## 3. 编辑态与发布态规则

### 3.1 数据边界

| 数据 | 表 | 说明 |
|---|---|---|
| 编辑态 | `qb_questions` | 管理端正在编辑的最新内容 |
| 发布态 | `qb_question_versions` | 用户端练习、考试、解析读取的稳定版本 |
| 附件编辑态 | `qb_question_attachments.question_version_id=0` | 草稿附件 |
| 附件发布态 | `qb_question_attachments.question_version_id=版本ID` | 发布版本附件 |

### 3.2 规则

1. 用户端永远读取 `qb_question_versions`，不直接读取 `qb_questions`。
2. 编辑已发布题目时，只修改 `qb_questions`，不修改旧版本。
3. 再次发布时生成新的 `version_no`。
4. 已有练习、考试、错题、收藏必须引用 `question_version_id`。
5. 下架题目不删除历史版本，只阻止新练习/新考试使用。

### 3.3 版本表补充字段

```sql
ALTER TABLE qb_question_versions
  ADD COLUMN version_status VARCHAR(20) DEFAULT 'active' COMMENT 'active/archived/deprecated',
  ADD COLUMN change_log VARCHAR(500) DEFAULT '' COMMENT '本次发布变更说明',
  ADD COLUMN visibility_snapshot JSON NULL COMMENT '发布时可见范围快照';
```

CREATE TABLE qb_question_logs (

## 5. 答案与解析可见策略

### 5.1 问题说明

发布后不代表任何时候都直接给用户答案。不同练习场景需要不同策略。

### 5.2 `qb_questions` 补充字段

```sql
ALTER TABLE qb_questions
  ADD COLUMN analysis_visible_policy VARCHAR(30) DEFAULT 'after_answer' COMMENT 'always/after_answer/after_exam_end/never',
  ADD COLUMN answer_visible_policy VARCHAR(30) DEFAULT 'after_answer' COMMENT 'always/after_answer/after_exam_end/never';
```

### 5.3 策略说明

| 策略 | 说明 |
|---|---|
| `always` | 只要有权限查看题目，就可看答案/解析 |
| `after_answer` | 用户提交答案后才可看答案/解析 |
| `after_exam_end` | 考试结束后才可看答案/解析 |
| `never` | 用户端永不展示，仅管理端可见 |

### 5.4 接口校验

`GET /api/v1/study/questions/:id/analysis` 必须校验：

1. 用户是否有题目可见权限。
2. 题目版本是否已发布。
3. 当前场景是否满足 `analysis_visible_policy`。
4. 如果是考试场景，必须确认考试已结束。
5. 如果是练习场景，必须确认用户已提交答案。

## 6. 回收站与恢复

### 6.1 题目软删除规则

`qb_questions.deleted_at` 代表软删除。删除题目时：

- 不删除 `qb_question_versions`。
- 不删除文件管理中的附件。
- 不删除历史答题记录。
- 用户端不再展示该题。

### 6.2 补充字段

```sql
ALTER TABLE qb_questions
  ADD COLUMN deleted_by BIGINT UNSIGNED DEFAULT 0 COMMENT '删除人 sys_users.id',
  ADD COLUMN recycle_expire_at DATETIME(3) NULL COMMENT '回收站过期时间';
```

### 6.3 接口与权限

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/v1/questions/recycle/list` | `question:delete` | 题目回收站列表 |
| POST | `/api/v1/questions/recycle/:id/restore` | `question:restore` | 恢复题目 |
| DELETE | `/api/v1/questions/recycle/:id` | `question:delete:permanent` | 永久删除题目 |
| DELETE | `/api/v1/questions/recycle/empty` | `question:delete:permanent` | 清空回收站 |

## 7. 来源关系修正

### 7.1 问题说明

`qb_question_sources` 表表示“来源”，例如一张真题试卷；题号应该属于“题目与来源的关系”，不应该只放在来源表里。

### 7.2 推荐新增表 `qb_question_source_relations`

```sql
CREATE TABLE qb_question_source_relations (
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  question_id BIGINT UNSIGNED NOT NULL COMMENT 'qb_questions.id',
  source_id BIGINT UNSIGNED NOT NULL COMMENT 'qb_question_sources.id',
  question_no VARCHAR(50) DEFAULT '' COMMENT '该题在来源中的题号',
  score DECIMAL(6,2) DEFAULT 0 COMMENT '原试卷分值，可选',
  created_at DATETIME(3) NULL,
  UNIQUE KEY uk_qb_question_source (question_id, source_id),
  INDEX idx_qb_question_source_question_id (question_id),
  INDEX idx_qb_question_source_source_id (source_id)
);
```

第一版可以保留 `qb_questions.source_id` 作为主来源，同时增加关系表，方便后续一题多来源。

## 8. 唯一约束与逻辑约束

### 8.1 建议唯一约束

| 表 | 唯一约束 | 说明 |
|---|---|---|
| `qb_exam_categories` | `(parent_id, name)` | 同父级考试大类不重名 |
| `qb_exams` | `(exam_category_id, name)` | 同大类下考试不重名 |
| `qb_subjects` | `(exam_id, name)` | 同考试下科目不重名 |
| `qb_categories` | `(subject_id, parent_id, name)` | 同科目同父级章节不重名 |
| `qb_knowledge_points` | `(subject_id, parent_id, name)` | 同科目同父级知识点不重名 |
| `qb_question_versions` | `(question_id, version_no)` | 版本号唯一 |
| `qb_question_visibility_scopes` | `(question_version_id, scope_type, scope_id)` | 可见范围唯一 |
| `qb_question_knowledge_points` | `(question_id, knowledge_point_id)` | 题目知识点不重复 |
| `qb_question_tags` | `(question_id, tag_id)` | 题目标签不重复 |

### 8.2 删除保护

- 考试大类有关联考试时不能删除。
- 考试有关联科目、题目、来源时不能删除。
- 科目有关联分类、知识点、题目时不能删除。
- 分类有关联题目或子分类时不能删除，需先迁移或合并。
- 知识点有关联题目时不能删除，需先解除绑定或合并。
- 标签有关联题目时不能直接删除，建议禁用或合并。

## 10. 安全与内容质量规则

### 10.1 富媒体安全

1. `text` 块如支持 HTML，后端必须做 HTML 白名单净化。
2. 禁止 `script`、`iframe`、`object`、`embed`、`form` 等危险标签。
3. 禁止 `onerror`、`onclick`、`onload` 等事件属性。
4. 图片、音频、视频、文档必须通过 `fileId` 引用系统文件，禁止直接使用外链。
5. 文件预览、播放、下载必须走权限校验。

### 10.2 AI 生成题规则

1. `source_type=ai_generated` 的题默认进入草稿或待审核。
2. AI 生成题必须带 `AI生成` 标签。
3. AI 生成题进入公共题库前必须人工审核。
4. 建议保留生成提示词摘要、模型信息、生成时间。

### 10.3 内容校验

发布前必须校验：

- 题型合法。
- 题干非空。
- 客观题答案合法。
- 解析结构合法。
- 附件存在且未删除。
- JSON 深度和大小不超过限制。
- 富文本安全。

## 12. 与学习/考试模块的边界

题库模块只负责题目、版本、附件、分类、知识点、来源、标签、审核和分享。

以下能力建议属于学习/练习或考试模块：

| 能力 | 建议模块 | 与题库关系 |
|---|---|---|
| 用户答题记录 | `study_` 或 `exam_` | 必须引用 `question_version_id` |
| 错题本 | `study_` | 引用题目版本，保留答题快照 |
| 收藏 | `study_` | 可引用题目或题目版本 |
| 试卷 | `exam_` | 试卷题目应引用 `question_version_id` |
| 考试记录 | `exam_` | 答题记录引用题目版本 |
| 正确率统计 | 统计模块 | 从学习/考试记录汇总到题库统计 |

核心规则：**凡是用户答过、考过、收藏过的内容，都应该引用发布版本 `question_version_id`，不能只引用编辑态 `question_id`。**
